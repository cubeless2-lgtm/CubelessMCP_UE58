# 언리얼 에이전트 협업

이 스킬은 Cubeless UE 5.8 프로젝트에서 적용한다. 대상 `.uproject`를 확인하고 [프로젝트 운영 지침](../../../cubeless/codex/AGENTS.md)과 [제작 흐름](../../../cubeless/codex/workflows/production.md)을 따른다.

## 작업 규모 결정

- **작은 작업**은 주 담당자가 계획부터 확인까지 직접 처리한다. 상태 조회, 범위가 분명한 단일 파일 수정, 되돌리기 쉬운 에셋 설정 변경이 여기에 해당한다.
- **큰 작업**은 결과를 검수할 기준을 먼저 세우고 계획·구현·독립 검수를 분리한다. 여러 기능이나 에셋의 변경이 연동되거나, MCP 호출 계약·공유 상태·런타임 의존성에 영향이 있으면 이 경로를 사용한다. 저장 동작 자체를 바꾸거나 대량 덮어쓰기 위험이 있는 작업도 포함한다. 지정된 에셋을 통상적으로 저장하는 것만으로는 규모 분류를 바꾸지 않는다. 파일 수가 적더라도 데이터 유실이나 수명 관리 위험이 크면 큰 작업으로 다룬다.

## 큰 작업의 역할과 인계

1. **계획 · 이에타**. 주 에이전트가 목표, 대상 경로, 수정 범위, 완료 조건과 검증 방법을 정한다. 에디터 작업이 필요하면 대상 프로젝트와 에디터 세션을 식별하고 변경 담당자 한 명을 지정한다.
2. **구현 · 티브렛 또는 티브렛 MCP**. 위임이 가능한 세션에서는 지정한 구현을 별도 에이전트에 맡긴다. 티브렛은 에셋 제작을, 티브렛 MCP는 도구 개발을 담당한다. 각 구현 담당자에게 정확한 파일·에셋 범위와 검증 조건을 전달한다. 병렬 구현은 파일과 변경 대상이 겹치지 않을 때만 진행한다. 구현자는 변경 목록, 빌드·컴파일·저장 상태, 실제 확인 결과와 남은 제한을 반환한다.
3. **독립 검수 · QA 또는 C++ 리뷰어**. 구현에 참여하지 않은 별도 에이전트에게 검수 대상 버전, 기대 동작, 변경 목록, 재현 방법과 근거를 전달한다. 검수자는 읽기 전용으로 검토하고 문제의 위치와 재현 조건을 보고한다. 에디터 변경이 필요한 검수는 지정된 변경 담당자가 실행하고 검수자가 결과를 대조한다. 수정이 필요하면 구현 담당자가 반영하고 검수자가 영향 범위를 다시 확인한다.

주 에이전트는 인계 결과를 확인하고 통합한다. 별도 에이전트나 독립 검수가 세션 제약으로 불가능하면 가능한 작업을 진행하고 독립 검수를 미실행으로 기록한다. 자기 검토를 독립 검수로 기록하지 않는다.

## 공유 에디터와 에셋의 수정 담당자

한 작업에서 **에디터 세션마다 변경 담당자 한 명을 지정하고, 같은 에셋·패키지는 작업이 끝날 때까지 한 명만 수정한다.** 맵 전환, PIE/SIE 전환, 에셋 편집, 컴파일, 저장, 에셋 상태를 바꾸는 검증은 모두 이 범위에 포함한다. 다른 에이전트는 해당 작업을 담당자에게 요청하고, 변경이 완료된 상태와 근거를 검토한다. 읽기 전용인지 확인할 수 없는 도구는 변경 담당자가 다룬다.

변경 요청이 타임아웃되거나 응답이 끊기면 담당자가 대상의 실제 상태를 확인할 때까지 같은 세션과 에셋의 후속 변경을 보류한다. 팀 구성과 인계는 프로젝트의 C++ 승인, 에디터 수명 주기, 저장·게시 권한을 그대로 따른다.
