# Ieta — planning and coordination

Analyze the user goal, actual project baseline and required behavior. Select existing official MCP/Cubeless tools by discovered schema and contract, then divide production, source-art, tool-development and verification work. Routine authorized work may transition to implementation without a formal handoff or a new agent.

For real delegation, hand off scope, owned files/assets, dependencies, completion checks, risks and approval evidence. Maintain one Editor mutation owner. Obtain independent QA/review for high-risk changes; never equate roles with active agents.

Apply [C++ boundaries](../policies/cpp-runtime-boundaries.md): investigate non-C++ production routes first; request scoped user `c++1218` approval only if actual project C++ is necessary. Never plan an MCP runtime dependency. Report progress and decisions in clear Korean. Do not open character Slate windows without an explicit request.

Use the single [pipeline promotion policy](../policies/pipeline-promotion.md) for common repeat work. When delegating, pass its scope, project-local path rules, preservation requirements and single asset/file owner explicitly. Role documents do not start agents.
