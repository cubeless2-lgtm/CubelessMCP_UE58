# 공통 반복 작업의 파이프라인 승격

승인된 실무 작업 중 반복 사용이 확인되고, 에셋·이름·경로를 입력으로 분리할 수 있는 공통 흐름은 기존 실행기에 통합할 수 있습니다. 같은 검증을 반복한 횟수는 실무 수요가 아닙니다. 한 번 성공했거나 횟수가 많다는 이유만으로 승격하지 않습니다.

입력·완료 기준·부분 실패·실제 변경·저장·보고 계약이 명확하고, 일반화할 경계와 재사용 효과가 유지 비용보다 클 때만 진행합니다. 기존 파이프라인과 공통 보조 코드를 먼저 재사용하고, 독립적인 목적이 있을 때만 새 진입점을 만듭니다. 대표 정상 흐름과 중요한 실패 경계, 지원 범위·예제·근거를 갖춘 뒤 사용 경로에 편입하고 이유와 결과를 보고합니다. 미검증 후보는 후보로 남깁니다.

특정 프로젝트·연출·게임 규칙에 종속된 흐름, 일회성 복구, 원인이 불명확한 우회, 실험, 새로운 외부 서비스·계정·비용·중대한 의존성, 공개 계약이나 승인 범위를 바꾸는 작업, 공통화 이점이 불명확한 작업은 사용자 요청이 필요합니다. 이미 승인된 BP·Niagara·PCG 편입에 다시 승인을 요구하지 않습니다.

승격 권한은 실행 권한과 다릅니다. 사용자 에셋 대량 변경·삭제·덮어쓰기와 Git stage·commit·push를 승인하지 않습니다. 실행은 원래 승인된 대상과 범위에서만 합니다. 상시 감시·스케줄러·서버를 만들거나 무관한 후보를 추가 구현하지 않습니다.

경로 기준은 실행 파일에 속한 식별된 `cubeless`와 바로 위 `.uproject`입니다. 하위 에이전트를 실제로 사용할 때는 승격 범위·특별한 흐름의 승인 조건·경로·보존 원칙과 단일 파일/에셋 소유권을 함께 전달합니다. 이 문서는 에이전트를 자동 실행하지 않습니다.
