# Actor fixture and official MCP pipeline

Source-only implementation on 2026-10-10; root owns every editor/API execution. Actor native M build and Python M2 activation are separate evidence. These scripts have not yet authored an actual UE Actor fixture or completed a cold verification.

## Files and sequence

1. `cubeless/tools/verification/create_actor_smoke_map.py`: root-run editor script with `--project-file <exact UE58Verification uproject> --report <fresh fixture JSON>`. Uses the installed public `EditorLoadingAndSavingUtils.new_blank_map(False)`, `save_map(world, package)`, then `load_map(filename)` to establish exact saved identity. It requires clean packages, stopped PIE/SIE and exact isolated project/UE5.8.3. It records pending creation/save, actual world identity, map SHA256, baseline actors and protected WorldSettings. This is fixture preparation, not a new registered MCP feature.
2. `cubeless/tools/pipelines/actor_mutation_smoke.py --endpoint <official MCP URL> --expected-project <exact UE58Verification uproject> --phase author --fixture-report <fixture JSON> --output <fresh author JSON>`. It discovers actual toolsets and schemas, refuses missing required/default arguments, and runs 49 named stages.
3. After root's clean shutdown/new editor process, run the same external script with `--phase reload --fixture-report <same fixture JSON> --parent-report <author JSON> --output <fresh cold JSON>`. A different native editor instance ID, identical saved bytes and actual level loading/readback are required. The cold phase changes the loaded editor context; it makes no Actor mutation/compile/save calls.
4. Independently run `cubeless/tools/verification/actor_pipeline_report.py <author-or-cold JSON> --fixture-report <fixture JSON> [--parent-report <author JSON>] --output <fresh verification JSON>`.

No command launches or stops an editor except root's own external orchestration. No server is started. No mutation is automatically retried and no cleanup is performed. All game-side objects are the existing Engine native classes and a blank map under `/Game/CubelessMCPTests/Actors_<UUID>/Map_Actors`.

## Actual public API/source basis

Installed `EditorToolset/Content/Python/editor_toolset/toolsets/scene.py` defines public `load_level(level_path)` and `get_current_level()`, but no blank-level creation tool. `actor.py` defines `set_label(actor,label)` with readback and `get_label(actor)`. `asset.py` defines exact-list `save_assets(asset_paths)` and `is_dirty(asset_path)`; this pipeline never passes an empty asset list (which would save all dirty assets). Installed `UEditorAssetSubsystem::SaveAsset` resolves the registered asset then saves its package through `EditorLoadingAndSavingUtils::SavePackages`; it does not reject a loaded World merely because it is a map. Actual save acceptance and disk/cold proof remain required.

`FileHelpers.h/.cpp` provides the fixture's exported `NewBlankMap`, `SaveMap`, `LoadMap`. The fixture records hashes of these source files. The native Actor header's six positional contracts were checked separately. The HTTP runner captures the current official registry schemas before any actor write; file-source API matching is not described as actual runtime registration proof.

Official string-returning tools return ordinary scalar strings for paths/labels. The runner and independent verifier decode these separately from Cubeless's native JSON-string envelopes. Synthetic integration tests caught and corrected the inappropriate second JSON parse of ordinary strings.

## Coverage and limitations

Authoring exercises the five original native types, uppercase type normalization, exact UObject names, the `create_actor` alias, default vectors/optional guard omission, display label changes and name-based search distinction, component-preserving partial transform, all-null no-op, durable replay/conflict, duplicate/missing actor errors, malformed vector rejection, wrong-level guard, protected WorldSettings deletion refusal, verified CameraActor deletion, full actor-state readback after each negative result, and exactly one final exact-map save. The saved map is then checked in a new editor process.

The verifier binds exact stage order, tool provenance/arguments, raw response, decoded response and stage result; validates actual before/after actor sets and transforms; checks the legacy mutation result markers/counters; and requires correct rejection categories and zero reported changes. Cold verification binds fixture and author hashes, exact file path/SHA256 and different editor identity. Persistence equality covers the owned `Cubeless_` actors and the protected WorldSettings; transient/system baseline actors can differ across processes and are not claimed to be persisted. All loaded rows remain in raw evidence, while within-author before/after comparisons still detect unexpected other actor changes. It does not trust stage `passed=true` alone. Unexpected negative acceptance is followed by one actor read and then stops without a save.

This does not verify arbitrary Actor/BP classes, attachments, streaming levels, World Partition, external actors, selection undo, rendering, delegates beyond native observation scope, package runtime behavior, the remaining 29 legacy editor tools, or full migration parity. The registered Actor first-slice restrictions remain explicit.

Offline evidence: 18 tests in `test_actor_pipeline.py` pass, including synthetic positive author/cold reports, raw/cached mismatch, wrong tool/name/class, label-vs-name confusion, transform component change, false no-op/replay, arbitrary-error substitution, negative-result state changes, omitted stages, file-owner escape, same-process cold claim, actual external runner string/void decoding, unexpected negative acceptance→readback→stop, allowed unrelated system-actor differences in cold load, and rejected unexpected owned actors. Synthetic evidence is not counted as UE execution. The actual root-captured M registry (`registered-schemas-and-diagnostics-M.json`) was read after activation: the Actor JSON-string vector defaults and optional guard/operation IDs are present, with only name/type required for creation.
