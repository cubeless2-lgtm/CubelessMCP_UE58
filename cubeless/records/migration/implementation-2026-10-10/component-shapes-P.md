# P: Shape 범위와 named mesh 파이프라인

P 증분 빌드와 공식 8 Toolset/41개 도구 등록, named mesh 기본값 저작·Shape batch·저장 및 대표 오류 거부가 통과했다. 새 프로세스 대표 조회도 통과했으며 전체 legacy 동등성은 미완료다. O의 원본 실행 보고서와 source SHA는 그대로 보존한다.

좁은 원본 조사에서 `Python/scripts/blueprints/test_create_and_spawn_blueprints_with_different_components.py`(inventory SHA-256 `1f6613f620e012ba9461ebedc9f1617bbc165b10f12b44af86e7866878d9d913`)의 Box/Sphere 충돌 시나리오를 확인했다. 호출 순서는 Actor BP 생성 → add_component_to_blueprint에 이름·identity transform·초기 속성 전달 → compile_blueprint → spawn_blueprint_actor다. Box는 BlockAll, Sphere는 OverlapAll 및 SphereRadius=100을 요청한다. 이 스크립트에는 Capsule 시나리오가 없다. 각 helper는 응답의 status=success만 검수하며 실패 시 해당 시나리오를 중단한다. main은 다음 시나리오를 계속 실행하고 성공 개수를 로그로 출력한다. 명시 저장·실제 속성 readback·독립 보고서는 없고, 계층 시나리오는 TODO로 비활성화돼 있다. 따라서 속성이 실제 적용됐다는 5.6 증거나 단순 3-shape 전체 이식 근거로 확대하지 않는다. FluidNinja/PCG 관련 스크립트는 이번 좁은 경로의 대응으로 사용하지 않는다.

기존 `component_authoring.py`의 선택된 큐브 흐름은 P의 named `set_static_mesh_properties(blueprint_name, component_name, static_mesh='/Engine/BasicShapes/Cube.Cube', operation_id=None)`로 mesh 설정을 호출한다. static_mesh를 생략해 기본 Cube 계약을 확인한다. O의 일반 typed setter 경로와 새 실행은 각 report의 source SHA·실제 호출로 구분한다. P에서는 새 map 없이 asset author만 실행하고, O의 이전 spawn/cold 결과를 P 실행으로 다시 계수하지 않는다. 원본 C++의 숨겨진 material → SetMaterial(0) 경로는 공개 Python wrapper에 없으므로 이번 named 도구에 포함하지 않으며 미완료로 남긴다.

대표 Shape 확인은 기존 `component_batch_smoke.py`의 선택형 `--shape-bounds` 경로로 묶는다. 새 UUID의 격리 Actor BP 하나에 SphereRadius=100, BoxExtent=[20,30,40], CapsuleRadius=30/CapsuleHalfHeight=60을 compile=false로 추가하고 SphereRadius=64 setter와 마지막 compile/save까지 5-child batch로 실행한다. 명시 compile/save 각 1회, 공식 ObjectTools의 세 template 크기 readback·계층·dirty 상태를 확인한다. 대표 부정 입력은 CapsuleRadius=61 > companion halfheight60이며 거부 뒤 두 크기·dirty·저장 bytes의 불변을 확인한다. 기존 O 배치 시나리오는 기본 경로로 유지하며 별도 검수 프레임워크나 기능별 패키징은 추가하지 않는다. 충돌 profile/물리 시뮬레이션/원본 spawn/기존 BP 재사용은 이 Shape 대표 확인의 검증 범위가 아니다.

공개 엔진 API와 실제 등록 스키마를 사용한다. 설치 UE58의 `SphereComponent.h:33` SetSphereRadius, `BoxComponent.h:39` SetBoxExtent, `CapsuleComponent.h:48` SetCapsuleSize는 ENGINE_API로 공개된다. raw/reflection 값 쓰기만으로 bounds/body setup 갱신을 대체하지 않는다. Capsule setter와 PostEdit가 companion 크기를 보정할 수 있어 유효한 최종 pair를 미리 검사한다. 구현 계약은 exact SphereComponent/BoxComponent/CapsuleComponent, 유한 비음수 크기 <=1e12, 최종 CapsuleRadius<=CapsuleHalfHeight다. 0 크기 저장은 물리 representation fallback의 동등성 증명이 아니다. 엔진 실행은 root 담당이며 pipeline은 정확한 UE58Verification 프로젝트/PID/초기 dirty/SaveOnCompile=Never와 새 경로만 허용하고 불확실한 변이를 자동 재시도하지 않는다.

실행 근거는 `build-component-P1.log`(6.77초), `registered-schemas-and-diagnostics-P.json`, `component-author-P.json`, `shape-bounds-P.json`, `actual-codex-negative-P.json`이다. asset-only cube author는 21 named calls/29 HTTP/1.0505173초로 named 기본 Cube → compile/save 각 1회를 확인했다. spawn은 이번 실행에서 pending이며 O2의 이전 완료와 구분한다. Shape는 15 named calls/23 HTTP/0.9452058초, 핵심 5-child batch 0.208877초(내부 0.16057초)다. 크기 3종의 공식 property readback과 Capsule61>60 거부 후 크기·dirty·저장 bytes 불변, 컴파일·저장 각 1회가 통과했다. 실제 Codex의 잘못된 mesh 조회도 `component_mesh_reference_invalid`/preflight/변경0/compile0/save0으로 거부됐다. 작은 warm 격리 fixture·NullRHI·loopback 단일 표본이며 속도 개선율을 주장하지 않는다. P 전체 배포 빌드·MCP 없는 패키징·물리 동작은 미검증이다.


새 PID 26272의 최종 근거는 `component-reload-P.json`(cube 9 calls/17 HTTP/0.3607934초), `actual-codex-cold-P.json`(Shape 계층·GUID·클래스·부모·transform/공식 크기 일치), `source-and-shape-persistence-P.json`(plugin 79파일 등록 snapshot 일치, Shape SHA/mtime 불변), `target-preservation-after-P.json`(기존 보호 1,059개 중 승인된 uproject 외 변경 0개)이다. cold 기록에 포함된 저장 의존성 조회는 두 BP root/재귀 7패키지, forbidden violations=[]/dirty=[]로 통과했다. 이 registry 층 증거는 패키징이나 물리 동작 검증이 아니다. O2의 map/spawn 검증은 이전 snapshot의 증거로 유지하며 P에서 반복하지 않았다.
