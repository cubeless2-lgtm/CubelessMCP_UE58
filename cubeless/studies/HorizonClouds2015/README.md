# Horizon Zero Dawn 구름: SIGGRAPH 2015 원문 학습

**현재 상태: UE 5.8 저고도 구름 학습 구현 사용 가능.** 원문 분석에 이어 실제 머티리얼·노이즈·맵을 제작하고 렌더·저장·재로드를 확인했습니다. [구현 결과·사용 방법·최종 코드](UE58_Implementation.md)를 함께 읽어 주세요. 원문의 전체 렌더링 시스템과 동일한 복제라는 뜻은 아닙니다.

## 출처와 이번 학습 범위

Andrew Schneider가 발표하고 Nathan Vos와 개발한 **The Real-time Volumetric Cloudscapes of Horizon: Zero Dawn**, SIGGRAPH 2015 발표 자료를 기준으로 정리했습니다. [Guerrilla 공식 소개](https://www.guerrilla-games.com/read/the-real-time-volumetric-cloudscapes-of-horizon-zero-dawn), [발표자 원본 PDF](https://d3d3g8mu99pzk9.cloudfront.net/AndrewSchneider/The-Real-time-Volumetric-Cloudscapes-of-Horizon-Zero-Dawn.pdf), [당시 강연 자료 목록](https://advances.realtimerendering.com/s2015/)에서 출처를 확인할 수 있습니다.

발표 슬라이드와 설명 노트가 함께 들어 있는 99쪽 PDF입니다. 아래 페이지는 **PDF 파일의 첫 페이지를 1로 세는 번호**입니다. 슬라이드에 인쇄된 번호와 다릅니다. 예를 들어 PDF 64쪽의 하단 번호는 62입니다. 2017년 Nubis나 이후 Nubis Evolved, 다른 엔진의 구현은 이번 원문에 섞지 않았습니다.

2026-10-26에 원문을 내려받아 99쪽 텍스트를 확인하고, 핵심 노이즈·높이·날씨·조명·샘플링·시간 재투영 도표를 렌더링해 읽었습니다. 원문에 명시된 스칼라 수식은 CPU 참조 계산으로 확인했습니다. 이 절의 원문 분석은 최초 학습 기록입니다. 이후 UE 5.8 실제 구현 결과는 [별도 구현 문서](UE58_Implementation.md)에 기록했으며, 발표자의 전체 비공개 셰이더와 화면을 정확히 복제했다고 주장하지 않습니다.

원본 식별: 6,015,654 bytes, SHA-256 `c3e26ceeaed9df84eb836fc92a6d2e720038b0d32a2414a2fdd1f831103aac32`.

## 원문의 실제 처리 흐름

```text
샘플 위치·고도·날씨 필드
  → 저주파 Perlin-Worley + 높이 프로파일로 큰 몸체 구성
  → coverage에 따른 범위 조정과 바닥 밀도 조절
  → 고주파 Worley로 경계 erosion, curl로 디테일 좌표 변형
  → 시선 방향 밀도 적분과 태양 방향 밀도 샘플링
  → Beer 감쇠 + HG 위상 + 시선 의존 powder 근사
  → 불투명도 누적·조기 종료
  → 이전 프레임 재투영과 저해상도 보완·확대
```

이것은 자료를 읽기 위한 단계 요약입니다. 발표자가 배포한 실행 코드나 정확한 노드 그래프는 아닙니다. 날씨 시뮬레이션도 별도로 존재하며 RGB가 곧바로 최종 구름 색이 되는 방식이 아닙니다.

## 2. 날씨: RGB 계약과 거리 정책

42쪽의 계약은 **R=coverage, G=precipitation, B=cloud type**입니다. B를 그대로 성장 높이(km)로 읽는 계약이 아닙니다. 강수와 구름 타입을 조합해 비구름을 만들며, 강수는 조명 흡수에도 관여합니다(44·70쪽).

47쪽에서는 플레이어 주변 반경 35 km에 구름을 그립니다. 15 km부터 수평선 쪽을 coverage 약 50%의 cumulus로 전환해 원경 구성을 유지합니다. 이것은 특정 신규 효과를 고정 원점에서 8~14 km에 걸쳐 끄는 RX 정책과 다릅니다. 원문 값을 프로젝트의 모든 맵에 적용해야 하는 보편 상수로 취급하지 않습니다.

## 3. 빛: 공개된 항과 공개되지 않은 결합 세부 사항

54~57쪽에서는 Beer 감쇠와 Henyey-Greenstein 위상 함수를 사용합니다. 57쪽에는 `Energy = exp(-d) * HG`가 표시됩니다. 59~68쪽에서는 표면보다 안쪽에서 입사광 산란 가능성이 증가하는 효과를 powder 근사로 설명하고, 시선·빛 방향 관계에 따라 효과가 달라져야 한다고 말합니다.

64쪽에 표시된 스칼라 항을 다음처럼 읽었습니다.

```text
B(d) = exp(-d)
P(d) = 1 - exp(-2d)
F(d) = B(d) * P(d)
```

여기서 `d`를 무차원 광학적 깊이로 두고 참조 계산했습니다. 물리량에 연결할 때는 일반적으로 `τ = ∫ extinction × density × ds`를 고려해야 합니다. 이는 학습용 해석이며, 발표자의 실제 코드에서 `d`를 구성하는 모든 계수·적분 방식이 공개됐다는 뜻은 아닙니다. `P`나 `F`를 최종 구름 alpha 또는 완전한 다중 산란 해라고 읽지 않습니다. HG의 실제 파라미터와 powder의 각도 혼합 계수까지 이 수식만으로 확정할 수 없습니다.

| d | Beer B | Powder P | 곱 F |
| ---: | ---: | ---: | ---: |
| 0 | 1.000000 | 0.000000 | 0.000000 |
| 0.1 | 0.904837 | 0.181269 | 0.164019 |
| 0.549306 | 0.577350 | 0.666667 | 0.384900 |
| 1 | 0.367879 | 0.864665 | 0.318092 |
| 2 | 0.135335 | 0.981684 | 0.132857 |
| 5 | 0.006738 | 0.999955 | 0.006738 |

곱은 표면에서 0이고, 어느 깊이까지 증가한 뒤 감쇠합니다. `F=e^-d-e^-3d`를 미분하면 최대 위치가 `ln(3)/2`, 최대값이 `2/(3√3)`입니다. 이 최대값 유도는 **이번 자체 계산**이며 발표자가 제시한 조절 상수로 추가하지 않습니다. 최소 재현은 표준 Python만으로 가능합니다.

```python
from math import exp, expm1, log, sqrt, isclose

def terms(d):
    b = exp(-d)
    p = -expm1(-2 * d)
    return b, p, b * p

assert terms(0) == (1.0, 0.0, 0.0)
assert isclose(terms(log(3) / 2)[2], 2 / (3 * sqrt(3)))
```

## 기존 RX 연구와의 정확한 관계

읽은 역사 자료는 원본 5.6 저장소의 `Docs/Analysis/RXSkyBaking_CoreGrowth_20260913.md`입니다. 원본은 수정하지 않았고 당시 성공·실패와 확인 범위를 현재 검증으로 승격하지 않았습니다.

| 항목 | 2015 원문 | RX 문서에 기록된 응용 |
| --- | --- | --- |
| 형태 단계 | 큰 몸체·높이 프로파일·경계 erosion 분리 | 중심 fullness·core preservation·경계 threshold·support를 추가한 RX 수식 |
| 지역 B | cloud type | 성장 두께 0.9~1.6 km 제어 |

| 원경 정책 | 플레이어 주변 35 km, 15 km부터 수평선 타입·coverage 전환 | 고정 원점 거리 8~14 km에서 신규 효과 fade |
| 왜곡 | curl로 고주파 노이즈 왜곡 | 몸체·support의 공유 변형 좌표와 소유 3D noise의 lobe 변형 |
| 산출물 | 런타임 구름 렌더링 시스템 설명 | 베이킹 레벨의 아트 검수 후보; 당시 전체 재베이크·cook/package는 미실행 |

RX는 원문의 설계 원리를 응용한 별도 구현입니다. RX의 저장 파라미터를 발표자 원래 값으로 소개하거나, RX 머티리얼을 원문 셰이더 그대로라고 표현하지 않습니다. RX의 기존 cold-load·오프라인 검사 증거는 UE 5.6 당시 해당 에셋의 근거이며 이번 UE 5.8 실행 증거가 아닙니다.

## 최초 원문 학습의 검증과 UE 구현 연결

**실행한 범위:** 원문 확보·99쪽 추출·핵심 도표 육안 확인, 위 수식의 경계·단조성·곱의 최대값·깊은 영역 감쇠 등 CPU 참조 검사 7개 통과. 보조 검사로 일정한 매질의 광학적 깊이 0.6을 64·128 구간으로 나눠 계산했을 때 alpha가 모두 약 0.451188로 일치했습니다. 이는 자체 해석 계산이며 발표자의 GPU 적분 코드를 검증한 것이 아닙니다. 양의 extinction 배율이 합성 밀도 배열의 수학적 support를 바꾸지 않는 점도 확인했습니다.

로컬 원시 기록은 `cubeless/records/operations/horizon-clouds-2015-study-20261026/`의 원본 PDF·취득 영수증·페이지 텍스트·도표 이미지·`reference-results.json`에 있습니다. 보조 `read_source.py`, `reference_checks.py`와 이 기록은 Git 제외 대상입니다. 이 Markdown은 별도 에셋이나 로컬 PDF 없이도 출처·처리 순서·참조 수식·검증 범위를 읽을 수 있도록 작성했습니다.

**현재 추가된 UE 구현:** 128³/32³ 노이즈, curl/weather, 저고도 Volume 머티리얼과 6개 MIC, 학습 맵을 `Content/Study/HorizonClouds2015`에 저장했습니다. 공식 MCP를 통한 GPU 컴파일·지상/상공 화면 비교·맵 재로드와 MCP 모듈 없는 새 프로세스 cold load를 확인했습니다. 원문에 공개되지 않은 생성 세부·높이/조명 계수는 자체 선택으로 구분했습니다.

**후속 범위:** 발표의 날씨 시뮬레이션 전체, 고고도 2D 층, 원래 시선 march/alpha 전환·시간 재투영 알고리즘의 정확한 재현, GPU 성능·베이크·패키징 게임 실행입니다. 현재 시선 적분·history는 UE 네이티브 구현을 사용합니다. 기본 구름 에셋은 사용 가능한 상태이며 위 항목은 그 사용을 막는 결함을 뜻하지 않습니다.

자체 리뷰에서 특히 RGB 의미, 고도와 두께, 로컬 밀도와 누적 alpha, 수학적 support와 화면 윤곽, 발표 성능과 현재 측정을 구분했습니다. 최종 원문 대조에서는 34쪽의 설명에 맞춰 두 번째 3D 텍스처를 ‘주파수가 증가하는 Worley’로 명시하고, 공개되지 않은 RGB 혼합 가중치를 fBm 구현으로 확정하지 않도록 보완했습니다. 원본 저장소·엔진·사용자 구름 에셋은 변경하지 않았고 Git stage·commit·push도 수행하지 않았습니다.

## Powder 시선 방향 후속 수정

UE 구현 리뷰에서 Powder 가중치의 방향이 원문과 반대임을 확인했다. HG는 유지하고 Powder에만 반대 부호의 각도 코사인을 적용했다. 태양을 바라보는/등지는 시점의 켜짐·꺼짐 비교, 공식 MCP 컴파일·저장과 최종 에셋 cold load를 통과했다. [수정 및 검증 수치](UE58_Implementation.md#powder-시선-방향-리뷰-수정)에 기록했다. 이전 화면 차이만으로 방향 정확성까지 확인됐다고 해석하지 않는다.

## 기존 VDB와 후속 Nubis 학습 연결

기존 UE56에는 VDB/SVT 기반 Volumetric Cloud와 28개 배치 편집 구현이 이미 있었다. 2015 절차적 Study와 별도로, 그 구조를 재사용하고 공식 VDB·공개 밀도 코드로 작성한 [HorizonNubis UE58 Study](../HorizonNubis/README.md)가 있다. Zero Dawn 2015, Forbidden West 2022, Burning Shores 2023의 채널·렌더러 차이를 구분했다. 2015의 Weather RGB와 NVDF의 profile/type/scale을 동일하게 해석하지 않는다.
