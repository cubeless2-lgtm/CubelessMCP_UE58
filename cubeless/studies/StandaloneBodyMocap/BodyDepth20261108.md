# 지지 다리 깊이 보정 (2026-11-08)

## 결과와 사용

`Refine Body from Video (Experimental)`을 추가했다. `Foot Locking`이 켜져 있을 때 선택할 수 있으며 기본값은 꺼짐이다. 기존 원본/고속 모델 선택과 독립된 후처리 옵션이며, 끄면 이전 전신 최적화 경로를 사용한다. 모델 가중치, 손 추론, 관절 제한은 변경하지 않았다.

개선은 부분적이다. test3 20.10초에서 화면 왼쪽 지지 다리(인물의 오른다리)의 실제 Manny 굽힘은 30.00° → 19.05°, 보정 소스는 18.54°다. 원시 Hue 추정은 31.39°였으므로 리타깃 이전에도 깊이 오류가 있었다. 다리가 완전히 펴지거나 모든 구간의 정확도가 좋아진 것은 아니다. 일부 발 관통과 영상 재투영 오차가 증가해 선택형 실험 옵션으로 제공한다.

## 원인과 공통 변경

문제 프레임에서 원시 모델의 무릎은 엉덩이·발목보다 카메라 쪽으로 약 9cm 나와 있었다. 기존 최적화의 2D 항에는 엉덩이 관절과 허벅지 방향이 빠져 있어 무릎·발목의 영상 위치만 비슷하면 깊이 굽힘이 남을 수 있었다.

새 경로는 엉덩이와 허벅지 영상 근거를 포함하고 전역 카메라 높이를 함께 맞춘다. 카메라 회전과 배율은 고정한다. 관절 신뢰도, 영상상 다리 펴짐, 예상 투영 길이 대비 관측 길이, 접지 확률이 모두 충분할 때만 무릎의 카메라 깊이 잔차를 줄인다. 가중치는 초기 관측으로 고정하고 5프레임 평균을 원래 가중치 이하로 제한해 근거 없는 프레임에 새로 활성화하지 않는다. 실제로 굽거나 짧게 투영된 다리는 항이 약해지거나 꺼진다.

이는 각도 상한/하한을 강제하는 관절 제한이 아니다. 영상 이름·시점에 대한 분기도 없다. 발 표면 정점의 지면 아래 잔차도 추가했지만 소스와 Manny 발 형상 차이 때문에 최종 메시의 관통을 완전히 막지는 못한다.

선택한 G 설정: Position=10, Contact=80, Height=40, Depth=200, Prior=0.2, CameraHeight=1, Iterations=300, Tolerance=1e-5. `cbm.Refine.*` CVar로 진단할 수 있다. `cbm.Refine.CheckGradient`와 `cbm.DumpStages`의 기본값은 0이다.

## 전체 프레임 비교

기준은 직전 subject-shaped bind 리타깃 수정까지 적용한 결과다. 같은 신경망 출력 캐시로 244/604개 샘플을 비교했으며 수동 정답 데이터는 없다.

음수 높이는 지면 아래다. test3 오른발 최저 높이는 -3.72 → -3.69cm로 거의 같고, -0.5cm 아래 프레임 수는 172 → 255로 늘었다. test2 오른발도 78 → 109로 늘었다. 반대로 발 들뜸 p95는 test2 왼발 3.36 → 1.96cm, test3 오른발 1.78 → 1.22cm로 줄었다. 발 높이 문제를 해결했다고 표현하지 않는다.

실제 Manny LOD0 발 주변 5,182개 정점과 스킨 가중치, 언리얼 본 변환으로 측정했다. 접지 마스크는 이전 소스 발 높이 10cm 미만·XY 속도 15cm/s 미만·연속 6프레임 이상으로 고정했다. 결과마다 유리한 접지 프레임을 고르지는 않았지만 실제 접지의 정답 라벨은 아니다.

test3의 신뢰도 높은 2D 관절 재투영 오차 중앙값은 왼다리 14.62 → 15.65px, 오른다리 16.11 → 15.52px다. p95는 24.30 → 30.40px, 26.56 → 33.60px로 악화됐다. 오른무릎 프레임 간 굽힘 변화 최대값도 26.14 → 30.16°로 증가했다. 영상 일치나 시간 안정성이 동일하게 유지됐다는 보장은 없다.

## 손 화면 문제

조사 당시 도구에는 test2 전신 시험본이 선택돼 있었고 HandEnhancedAnimation이 비어 있었다. 기존 MediaPipe 관측을 새 전신에 재적용했다. 새 손 추론이나 손 모델 수정은 하지 않았다. 양 영상에서 손가락 이외 123개 트랙의 최대 차이는 0이다. 이전 보강 결과와 새 결과의 손가락·중수골 38개 본 로컬 회전도 전체 프레임에서 차이 0이다.

사용자 첨부 이미지의 정확한 프레임은 특정하지 못했다. 따라서 그 이미지의 자세까지 해결됐다고 결론내리지 않는다. 이번 전신 보정이 손 회전을 새로 망가뜨린 수치적 증거는 없으며 기존 손 추론의 가림·접촉·비정상 자세 한계는 남는다. 최종 도구에는 test3 새 전신 + MediaPipe 결과를 연결했다.

## 검증과 재현

- 같은 프로젝트 Development Editor 최종 빌드 성공: `build5.log`, 16.47초. 정상 종료 후 같은 프로젝트를 재시작했다. 최종 PID10496. 별도 에디터/컴퓨터 유즈 없음.
- 실제 입력의 깊이 항 미분 검사 각 36개 변수: 최대 절대 오차 test3 0.00001008, test2 0.00000394. 독립 FK와 네이티브 소스 위치 차이 0.00008cm 미만.
- G 실행: test2 `B06F1AE441E5CD15A2C7DFAE85FD6499`, test3 `A35003134E10732369BA559BFFF951E1`. 캐시 재사용 시간 14.47초/33.79초. 전체 영상 추론 속도 벤치마크가 아니다.
- 마지막 빌드는 선택한 G의 기본값·옵션 설명·프로파일 표기만 변경했다. 재시작 후 기본값과 에셋 재로드를 확인했으며 추출 전체를 다시 반복하지 않았다. 새 프로파일 필드의 작업 출력은 아직 확인하지 않았다.
