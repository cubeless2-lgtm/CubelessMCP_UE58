# CHMR 후속 레이아웃 최적화 실험 — 2026-11-12

## 결론

후속 개선 후보를 같은 Unreal 프로젝트의 GPU 실행으로 시험했다. 계산 결과는 유지됐지만 핵심 추론 시간 차이는 약 0.075%로 유의미하지 않았다. 기본 경로로 승격하지 않았고, 시험용 native 선택 코드를 제거해 이전 검증 소스와 SHA256까지 같은 상태로 복원했다. 기존 SAM2 rows512 및 렌더링 일시정지 개선은 유지한다.

## 후보

최종 전체 모캡에서 CHMR은 221.45초, Backbone RunSync만 203.52초로 가장 긴 단계였다. 기존 fused CHMR 모델에서 각 attention의 `Transpose → scalar Mul → inverse Transpose`를 원래 축의 동일 scalar Mul로 바꿨다. 24개 블록의 Q/K 두 분기에 있는 Transpose 96개를 제거해 935→839개 노드가 됐다.

스칼라 곱과 기존 Cast를 유지해 정밀도와 반올림 위치를 바꾸지 않았다. 원본·기존 fused 모델은 수정하지 않았다. 모든 initializer 텐서 바이트 지문과 모델 입출력 계약이 같다. 원본 fused 모델 SHA256은 `0e7de43e3a4d1f64640fc65cd052fcb73b836d537d172793dc61837fac30cf3f`, 후보는 `7e022d710c19e3aff09a329f7f969fcfa71a835163c43e83ceeb886bb8cea3f1`이다.

CPU에서는 Q/K 각 4,195,328개 원소의 분기 출력을 비교해 바이트가 같았다. 이는 전체 GPU 모델의 품질 검증과 별도 검사이다.

## 실제 Unreal GPU 비교

UE5.8.4 CL58902052, RTX5060 Laptop8GB, 동일 프로젝트와 단일 에디터에서 순서대로 실행했다. 기존 YouTube 5u6yVQ 45–60초 CW90 결과의 앞 32프레임을 사용했다. 기존 추출 프레임, 30fps, Manny·Retargeter, rows512, 렌더링 일시정지 설정이 동일하며 추론 체크포인트 재사용은 껐다. 손 보강·후처리는 이 짧은 성능 시험에서 공통으로 껐다. GPU 온도·클록까지 고정한 반복 통계 실험은 아니다.

| 항목 | 기존 fused CHMR | 레이아웃 후보 |
|---|---:|---:|
| CHMR Backbone RunSync | 14.34649초 | 14.33567초 |
| CHMR 전체 (초기화·전처리·Head 포함) | 17.27335초 | 16.51589초 |
| 짧은 전신 실행 전체 | 57.63819초 | 58.49044초 |

Backbone의 약 0.01082초 차이는 약 0.075%이다. CHMR 전체의 차이는 핵심 추론의 가속으로 이어지지 않았으며, 키포인트 등 다른 단계의 변동도 있었다. 런타임이 유사한 레이아웃 최적화를 이미 수행했을 가능성은 있지만 최적화된 실행 그래프를 추출해 확정한 것은 아니다. 단일 비교의 작은 차이를 가속 성과로 보고하지 않는다.

두 실행의 전체 TrackingBoxes·Keypoints·CHMR_Tokens MD5가 일치했다. 이는 32프레임 중간 결과 보존 검증이며, 후보의 450프레임 최종 손 보정 애니메이션 비교는 실행하지 않았다. 속도 이득이 없어 후보를 승격하지 않았으므로 동일한 장시간 검증을 반복하지 않았다.

## 복원과 증거

- 원시 증거: `cubeless/records/verification/chmr-layout-20261112/`.
- 후보 생성 및 CPU 검사: `prepare-candidate.py`, `candidate.json`.
- GPU 비교: `layout-reference-a.json`, `layout-candidate-b.json`, 각 GPU CSV 및 로그, `result.json`.
- 시험용 C++는 모델 선택 CVar·프로파일·캐시 구분만 추가했으며 작업 스레드 구조나 공개 API는 변경하지 않았다. 실험 뒤 이전 소스 지문과 정확히 같게 복원했다(`restore.json`).
- 미저장 패키지·PIE·작업이 없음을 확인하고 검증 에디터 PID23128을 정상 창 닫기로 종료했다. 다른 사용자 작업과 기존 dirty 파일은 보존했다.
- 복원 후 같은 프로젝트 Editor 타깃 빌드는 성공했으며 `build-restored.log`에 기록했다. 기존 450프레임 품질 검증은 동일한 복원 소스에 대해 그대로 유효하며, 이번에 다시 실행했다고 주장하지 않는다.
