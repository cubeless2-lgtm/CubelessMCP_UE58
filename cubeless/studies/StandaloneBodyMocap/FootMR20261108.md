# FootMR 발 보강 및 비교 카메라 검증 — 2026-11-08

FootMR을 선택 가능한 별도 발목 보강 경로로 구현하고 test2 전체 244프레임, test3 전체 604프레임에 적용했다. 전신과 HandFlow는 재추출하지 않았다. **이 두 영상에서는 접지 품질이 일관되게 좋아지지 않았으며 침투·지지 구간 발바닥 이동이 증가했다. 기본값은 보강 없음으로 유지한다.** 결과를 삭제하거나 원본과 자동 혼합하지 않고 직접 비교할 수 있도록 남겼다.

첨부된 test3 포즈 차이에는 비교 카메라 불일치와 기존 전신 추정의 깊이 오류가 함께 있었다. 카메라를 수정했으며 전신 애니메이션은 보존했다. 관절 제한은 추가하지 않았다.

## 구현

- `Feet > Foot Backend`: No foot enhancement / FootMR. HandFlow 손 기본값, 기존 손 방식, 원본·고속 전신 옵션은 유지.
- `Foot Input Animation`: 이미 HandFlow 등을 적용한 저장된 애니메이션. 별도 Feet 출력 애셋 생성.
- `Refine feet`, `Apply cached feet`, `Before feet`, `FootMR` 버튼. 기존 외부 Python 비동기 작업과 취소 경로 사용.
- FootCache 분리. 영상 내용, 숫자 입력, 체크포인트, 네트워크/작업 코드, 실행 버전 변경 시 무효화. 손 모델의 변경만으로 같은 전신에 대한 FootMR 추론을 반복하지 않음.
- FootMRInput.json과 작은 전신 숫자 입력을 전신 추출 시 저장. 이전 test2/test3 결과는 이미 검증한 Optimizer_Pose/Keypoints25/Camera와 TrackingBoxes MD5가 일치하는 캐시에서 이관. 전신 추론 재실행 없음.
- 결과 feet.json에 출처·모델·환경·검출 누락·처리 시간·RAM·CUDA allocator 메모리 기록.
- 저장된 전신과 선택한 손 보강 입력의 비손 트랙이 같아야 함. 이미 발 보강한 결과에 대한 중복 적용, 다른 소스 GUID, 잘못된 시간 범위를 거부.
- 관절 제한, WiLoR 혼합, 손 재추론, 전신 이동, 무릎 수정, 지면 스냅 없음.

관련 소스: `Plugins/CubelessBodyMocap/Source/CBMEditor/Private/CBMFeet.inl`, `CubelessMocap.cpp`, `CubelessMocapModule.cpp`, `SCBMComparison.cpp`, `Public/CubelessMocapSettings.h`, `Tools/run_foot_worker.py`, `Tools/prepare_footmr.py`.

## 모델과 변환

공식 [FootMR](https://github.com/twehrbein/FootMR) 리비전 `530da95641f906b42ba6792df8e55c1dd667f98d`의 FootEncoderRoPE, attention, rotary embedding 세 파일만 가져왔다. 가중치의 `pipeline.foot_motion_refiner.*` 127개 텐서만 추출했다. GVHMR 전신 추론이나 전체 애플리케이션은 편입하지 않았다. 추출 가중치는 약 14.6 MB이며 로컬에 준비됐다.

SMPL-X 전역 무릎 4/5와 발목 7/8을 원래 카메라 좌표계로 변환하고 기존 ViTPose WholeBody의 8개 발 관절 관측을 입력한다. FootMR 출력은 2개 발목의 카메라 전역 회전이다. 기존 무릎 회전으로 로컬화하고 원본 대비 회전 델타를 UE XZY 기저로 한 번만 변환했다. native retargeter의 발목 기저를 측정하여 Manny에 적용했다.

- native 3축 회전 probe 최대 차이: 0 rad.
- 전 프레임 원본 SMPL→Manny 발목 기저 변화: 최대 0.00033도 미만.
- 모델 출력→실제 Manny 발목 회전 차이: test2 최대 0.000078도, test3 최대 0.000160도.
- 두 영상 모두 **발목 외 159개 본 트랙의 데이터 차이 0**. 발목 위치·스케일도 차이 0. 전신·손·발가락 로컬 회전 보존.

발가락 로컬 회전은 같아도 부모 발목 회전 때문에 발가락 월드 위치는 바뀐다. 이는 보존 검사의 범위와 구별한다.

별도 venv에서 기존 손 환경의 torch/timm/einops/scipy/psutil 패키지를 읽기 전용으로 공유한다. 기존 환경에 pip 설치나 패키지 교체를 하지 않았다. 정확한 출처·변경·해시는 ThirdParty/FootMR/manifest.json과 NOTICE.md에 기록했다. upstream LICENSE는 연구/교육/비영리 용도로 제한하며 상용 이용 허가를 확인한 상태가 아니다. 별도의 가중치 재배포 허가도 주장하지 않는다.

## 속도와 메모리

UE 5.8.4 CL58902052, 기존 Windows/CUDA 환경에서 측정했다. 아래 시간은 **전신·손 캐시를 재사용한 발 보강 및 새 애셋 저장 시간**이며 전체 모캡 추출 시간이 아니다. 두 native 실행 모두 FootMR 모델 캐시 미적중이었다.

| 영상 | 전체 프레임 | 에디터 발 보강 작업 | 외부 Python 작업 | Python 최대 RAM | CUDA allocator 최대 사용 |
|---|---:|---:|---:|---:|---:|
| test2 | 244 | 4.92초 | 3.71초 | 1191.9 MiB | 32.4 MiB |
| test3 | 604 | 6.52초 | 5.29초 | 1173.2 MiB | 45.1 MiB |

RAM은 외부 작업 프로세스 RSS이며 에디터 메모리와 별개다. CUDA 수치는 PyTorch 할당량이며 드라이버/컨텍스트를 포함한 전체 VRAM이 아니다. test3 모델 캐시 적중 재실행은 1.74초, 437.5 MiB였다. 캐시 결과는 원시 회전 배열을 그대로 재사용한다.

test3 처리 중 Slate 틱 370회를 기록했다. 간격 중앙값 16ms, 95백분위 31ms, 최대 281ms. 외부 추론 중 에디터 루프가 진행됐고 전체 처리 시간 동안 멈추지 않았다. 최종 native 애셋 쓰기·압축은 여전히 게임 스레드에서 짧게 실행된다. 실제 마우스 조작 자동화는 사용하지 않았다.

## 발 품질 비교

동일한 Manny LOD0 발 정점과 변경 전 source motion에서 정한 고정 지지 마스크를 사용했다. 아래 이동 속도는 동일 마스크에서 발바닥 중심의 수평 속도 95백분위다. 실제 영상의 정답 접촉 라벨이 아니므로 절대 정확도로 해석하지 않는다.

| 영상 / 발 | 보강 전 → FootMR 발바닥 속도 | 전체 구간 최저 발 표면 높이 |
|---|---:|---:|
| test2 왼발 | 13.75 → 25.40 cm/s | −0.49 → −6.13 cm |
| test2 오른발 | 17.99 → 47.71 cm/s | −1.70 → −4.42 cm |
| test3 왼발 | 13.75 → 29.27 cm/s | −2.29 → −6.88 cm |
| test3 오른발 | 21.05 → 42.14 cm/s | −1.98 → −7.20 cm |

모델 로컬 발목의 프레임 간 회전 변화 최대값은 test2 21.15→20.97도, test3 26.55→24.27도로 줄었지만, 95백분위는 각각 7.41→8.78도, 6.77→8.10도로 증가했다. 따라서 “시간축 모델이라 모든 움직임이 더 부드럽다”고 결론 내리지 않는다.

발별 4개 관측이 모두 confidence 0.5 이하인 프레임은 test2 양발 0, test3 왼발 7/오른발 0이었다. 누락은 결과에 그대로 기록했으며 다른 모델이나 원본 회전으로 구간 교체하지 않았다.

회전 변환 오차는 위와 같이 매우 작다. 접지 악화는 현재 전신의 고정된 발목 위치와 FootMR이 바꾼 발 방향, 신체/발 형상 차이의 불일치로 해석한다. 공식 GVHMR 대신 현재 CHMR 기반 전신을 조건으로 사용한다는 입력 분포 차이도 남아 있다. 이 검증으로 FootMR 일반 성능이 나쁘거나 모든 영상에서 좋다는 결론을 내리지 않는다.

## 첨부 포즈: test3 20.03초

실제 점검 프레임은 601/30초다. 영상과 애니메이션 평가 시점은 0.002초 이내로 맞았다.

기존 비교 뷰는 수평, 수평 FOV 38도의 임의 front camera였다. 전신 추정에 사용된 test3 카메라는 pitch −12.43도, roll 약 −1.18도, 수평 FOV 약 22도다. `Preview > Match Video Camera`를 추가하여 해당 추정 기저와 초기 인물 상자를 이용한 근사 크기·위치를 적용했다. 기존 수평 비교도 체크를 끄면 볼 수 있다. 바뀐 것은 프리뷰 카메라이며 애니메이션 데이터는 변하지 않았다. Lumen/TemporalAA/MotionBlur는 계속 꺼져 있고 밝은 스튜디오 조명을 유지한다.

| 신체 기준 다리 | 원시 CHMR 무릎 굽힘 | 기존 영상 보정 후 | Manny |
|---|---:|---:|---:|
| 왼다리(화면 오른쪽) | 50.93도 | 48.35도 | 48.62도 |
| 오른다리(화면 왼쪽, 더 곧아 보이는 쪽) | 30.30도 | 18.55도 | 19.06도 |

화면 왼쪽 다리의 영상 2D 관측 굽힘은 약 8.78도다. 2D 각도와 3D 실제 각도를 같다고 볼 수는 없지만, 원시 전신부터 남는 깊이 모호성의 근거다. 옷에 가린 무릎에도 ViTPose가 약 0.79/0.89 confidence를 주므로 검출 confidence만으로 정답 관절이라고 판단할 수 없다. 리타깃이 큰 굽힘을 새로 만든 상황은 아니다. 전신을 보존한다는 이번 요구에 따라 강제 무릎 펴기나 관절 제한을 넣지 않았다. 골반·몸통을 포함한 남은 전체 자세 차이의 완전한 교정은 이번 결과로 검증하지 않았다.

## 검증·인계

- Development Editor 빌드 성공: 최초 32.44초, 카메라 보완 빌드 23.67초.
- 잘못된 소스 GUID, 중복 발 보강, 보강 없음 상태에서의 추론 시작을 거부하는 경로 확인.
- 모델 파일 누락 안내 확인. 취소는 0.3초에 종료 상태를 기록했고 기존 애셋/dirty package 변화 없음.
- 모델 결과와 Manny 결과를 전 프레임 숫자로 비교. 기존 카메라 캡처 52개, 카메라 수정 비교 캡처 18개 저장.
- 현재 사용자 에디터 PID 6800, test3 20.03초 일시정지, HandFlow 유지/발 보강 전 선택. `Before feet` / `FootMR` 버튼으로 비교 가능. FootMR 기본값은 None. Dirty package 없음.
- 원시 증거: Saved/CubelessBodyMocap/FootMRIntegration20261108/. 최종 기계 판독 기록: cubeless/records/verification/cbm-footmr-20261108.json.
- 설치 스크립트의 새 PC 전체 다운로드 경로, 일반 신규 전신 solve의 sidecar 생성 경로는 추가 전체 추출을 피하기 위해 실행하지 않았다. 기존 두 영상의 이관된 캐시에 대한 종단 실행을 검증했다.
- 독립 코드 리뷰는 수행하지 않았다. 별도 리뷰와 사용자의 최종 육안 평가가 남아 있다. 다른 하드웨어·스켈레톤·30 FPS 외 영상은 검증하지 않았다.

에디터 재시작 후 저장된 결과는 각 `/Game/_MCP_Temp/FootMR/CubelessTests/20261108_R1/test2/Feet/`, `test3/Feet/` 폴더에서 찾을 수 있다. Foot Input Animation에는 보강 전 HandFlow 결과를 선택하고 해당 영상·Foot Result를 지정한다. 모델 실행 없이 비교 버튼을 다시 채우려면 Apply cached feet를 사용한다.
