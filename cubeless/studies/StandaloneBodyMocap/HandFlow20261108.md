# 선택형 HandFlow / HaMeR 손 보강

2026-11-08, UE 5.8.4 CL58902052. 기존 CubelessBodyMocap 작업의 `c++1218` 승인 범위에서 Editor 플러그인과 외부 worker를 수정했다. 컴퓨터 유즈, 별도 프로젝트, 전신 재추출, 관절 제한, 모델 간 자동 혼합은 사용하지 않았다.

## 구현과 선택 방법

`Hands → Finger Backend`에서 `Existing - WiLoR + MediaPipe` 또는 `Temporal - HandFlow / HaMeR`를 선택한 뒤 `Refine fingers`를 실행한다. 기존 `MediaPipe only (legacy / diagnostic)` 항목과 그 기본값도 보존했다. `No hand enhancement`는 기존 전신 결과의 기본 손을 보여주는 비교 버튼이며 추정 모델이 아니다.

실제 기존 코드를 확인한 결과 WiLoR가 손 회전을 추정한다. MediaPipe는 독립 손 관측으로 좌우 식별/손 위치와 2.0·1.6 크롭 후보 선택을 보조한다. MediaPipe 회전을 WiLoR에 섞지는 않는다. 기존 spike/gap 필터와 보조 관측 부재 시 WiLoR 단독 fallback도 유지했다.

새 경로는 손 검출 → HaMeR 영상 특징/관절 조건 → HandFlow 시간축 추론이다. WiLoR 포즈를 입력받는 필터가 아니다. 두 경로 모두 같은 Original Animation을 복제하고 공통 Manny 손 리타깃에 연결한다. 결과는 다른 이름의 에셋으로 저장하며 이전 결과는 덮어쓰지 않는다. 현재 비교 창에서 원본/WiLoR/HandFlow/기존 MediaPipe를 동일 미디어 시각으로 전환할 수 있다. 원본 에셋이 달라지면 이전 비교 슬롯은 사용할 수 없도록 했다.

원본·고속 전신 옵션과 MetaHuman 비의존 구조는 유지했다. 전신 추출 변경은 새 비교 슬롯을 초기화하는 부분뿐이다. 새로운 runtime 모듈이나 출력의 Python/MCP 의존성을 추가하지 않았다.

## 좌표와 리타깃 확인

- 공통 출력: 왼손/오른손 순서, MANO의 index·middle·pinky·ring·thumb 각 3개 관절, flat-hand 물리 로컬 회전, xyzw quaternion. 손목/global orientation/translation은 제외한다.
- HaMeR의 21점 OpenPose 관절 순서는 영상 조건에 사용하며 15개 MANO 회전 순서와 혼동하지 않는다.
- HandFlow의 통계 역정규화는 upstream 추론 함수가 수행한다. 해당 MANO 평가 코드의 `flat_hand_mean=True`를 확인했다. 우리 어댑터는 MANO/SMPL-X 평균 자세를 더하거나 빼지 않고 PCA 축소도 하지 않는다.
- 왼손은 canonical right 결과를 `M R M`, `M=diag(-1,1,1)`로 한 번 반사한다. 이후 공통 `hand_contract.py`에서 SMPL→UE `C(x,y,z)=(x,z,y)`, quaternion vector `-C*v`를 한 번 적용한다.
- 기존 네이티브 palm-frame/terminal-axis 보정과 실제 출력 부모 기준 rebase를 그대로 공유한다. 참고 앱의 Blender/Mixamo finger retarget 코드는 중복 적용하지 않았다.
- 30개 손가락과 기존 처리 범위인 8개 중수골 회전만 변경한다. 양 경로와 기존 MediaPipe 재적용 모두 비손가락 123트랙의 전체 프레임 값이 정확히 같았다. 별도 Python 평가에서도 양 손목 quaternion 성분 차이는 0이다.

## 모델·실행·캐시

HandFlow 가중치 약 668MB, HaMeR 약 2.69GB, detector, 통계·설정·평균 파일과 사용자가 공급한 MANO_RIGHT.pkl을 로컬에 준비하고 SHA256을 확인했다. 새 venv는 기존 WiLoR 패키지 디렉터리를 읽기 전용 `.pth`로 참조하고 추가 패키지는 자기 디렉터리에 설치한다. 기존 WiLoR/MediaPipe 패키지는 수정하지 않았다. 따라서 현재 설치는 기존 WiLoR base 환경을 유지해야 한다. 완전 독립 설치 방법과 필요한 파일은 [준비 안내](../../../Plugins/CubelessBodyMocap/ThirdParty/HandFlow/README.md)에 있다.

기존 외부 Python 비동기 실행/취소 구조를 사용했다. 손 캐시는 `Saved/CubelessBodyMocap/HandCache`에 별도로 저장한다. 영상·디코딩 프레임·키포인트·FPS/구간·기준 형상·카메라·설정·모델·관련 Python 코드·패키지 버전이 서명에 포함된다. WiLoR가 별도로 실행하는 MediaPipe 환경 버전도 포함한다. 완성된 세대만 게시하고 파일 해시를 확인해 읽는다. 원본 에셋 식별자는 캐시 재사용 시 현재 원본에 다시 연결한다. 현재는 캐시 조회 전 영상 디코딩과 손 배정용 ViTPose를 실행하므로 그 비용까지 사라지는 캐시는 아니다.

파일이 없으면 누락 경로와 준비 방법을 안내한다. 파일 존재 확인과 worker의 실제 import/해시 검사를 구분했다. 처리 방식·설정·모델/코드 해시·누락 상태·시간·메모리는 request/identity/metrics/hands 및 네이티브 preservation 기록에 남긴다. 진행 표시의 worker `Completed`가 전체 작업 완료처럼 표시되던 문제도 `Finger worker:` 접두사로 구분했다.

## test2 실제 비교

동일한 기존 전신 `Body_B06F1AE441E5CD15A2C7DFAE85FD6499`, Manny, RTG_CBM_SMPL_to_Manny, 30fps, 244샘플(끝 시각 8.10초), Hand Strength=1을 사용했다. 전신 추출은 0회다.

| 항목 | WiLoR + MediaPipe | HandFlow / HaMeR |
|---|---:|---:|
| 손 처리 전체 실행 | 181.89초 | 80.8초 |
| 외부 worker 실행 | 155.58초 | 56.86초 |
| worker 프로세스 트리 RSS 피크 | 5,647MiB | 6,777MiB |
| PyTorch CUDA 할당 피크 | 2,698MiB | 2,788MiB |
| 검출 프레임 좌/우 | 235 / 141 | 237 / 172 |
| Manny 손가락 프레임 변화 p95 | 13.94° | 8.96° |
| Manny 손가락 최대 프레임 변화 | 41.54° | 75.02° |

실행 당시 관측값이며 일반적인 속도 보증은 아니다. 각 프로세스 피크를 더해 동시 전체 RAM으로 해석하지 않는다. WiLoR의 MediaPipe 보조 관측은 약 94.94초였다. HandFlow 검출 누락 좌7/우72프레임은 시간축 예측으로 채워졌지만 새로 관측한 손은 아니다. WiLoR의 원본 fallback은 우21프레임이었다.

구간별 결과는 다음과 같다.

- **3.20초:** 현재 구현에서는 양 방식 모두 양손 검출이 있었다. 이전 누락 문제의 현재 상태를 확인한 것이며 HandFlow만 새로 복구했다는 뜻은 아니다. HandFlow 왼손의 해당 프레임 최대 변화는 약20.77°로 WiLoR 9.81°보다 크다.
- **5.50초 손 겹침:** 양쪽 모두 오른손 raw 검출은 없다. WiLoR는 기존 fade, HandFlow는 시간축 예측을 적용한다. HandFlow의 작은 변화량을 정확한 가려진 손 복원으로 간주하지 않는다.
- **7.70초:** WiLoR가 검지·새끼손가락을 편 원본 제스처에 더 가깝다. HandFlow는 두 손가락이 굽어 제스처를 놓친다. 모델 출력과 Manny 화면 모두 비교했으며 HandFlow가 더 좋다고 결론내리지 않는다.
- **추가 7.03초(frame211):** HandFlow 왼손 `pinky_01_l`에 75.02° 변화가 있다. 모델 출력 75.0152°, Manny 75.0152°로 리타깃 이전부터 존재한다. 관절 제한이나 다른 모델로의 구간 교체로 숨기지 않았다.

빠른 동작에 대한 시간 이동은 적용하지 않았고 프레임/FPS는 같다. 다만 이것이 지각적 지연 0의 증거는 아니다. 독립 MediaPipe 2D PIP 곡률과 모델 3D 곡률의 교차상관 보조 검사는 WiLoR 대부분 0~1프레임, HandFlow -5~+6프레임으로 분산됐다. 2D 투영·가림·자세 오차가 섞여 있고 낮은 상관도 있으므로 정답 지연 측정값으로 쓰지 않는다. HandFlow의 작은 변화량은 빠른 제스처를 약화한 결과일 수도 있다. 미래 프레임을 사용하는 offline 추론이며 streaming 지연 보장은 없다.

원시 HandFlow MANO 투영에는 위치/크기 오차도 관측됐다. 해당 모델의 global pose/translation을 Manny에 적용하지 않았으므로 손 형태 검사와 원시 투영 정확도를 구분한다. `model_comparison.png`는 영상에 맞추기 위한 정렬을 하지 않은 raw 투영 비교다. 검출 crop이 없는 프레임은 투영 불가로 표시했다.

## 검증 범위와 실패 기록

- 같은 프로젝트 Editor 빌드 2회 성공, 최종22.95초. 정상 종료·재시작 후 기존 결과 재로드와 새 결과 저장/직접 의존성을 확인했다. 최종 PID29012, test2 7.70초 왼손 HandFlow 미리보기와 비교 버튼을 유지했다. dirty package 없음.
- 실제 네이티브 HandFlow 처리 중 Slate callback 241회, wall gap 최대1.417초. background editor의 통상 간격은 약0.333초였다. 장시간 추론 전체를 game thread에서 막지는 않았으나 초기 준비/저장의 순간 지연까지 없다는 보장은 아니다.
- 실행 중 Python 단계 취소를 검증했다. 해당 작업은 Cancelled로 종료되고 새 손 에셋은 생성되지 않았으며 해당 worker 프로세스도 남지 않았다. 이후 명시적으로 새 작업을 실행해 완료했다.
- 동일 입력 HandFlow 재실행의 quaternion 성분 차이는 0이었다. HandFlow prediction cache hit는4.38초, 재추론 없이 동일 자료를 반환했다. 최종 telemetry-only 수정 후에는 기존 MediaPipe 2프레임 처리와 cache hit도 확인했다. 기존 MediaPipe 환경에 psutil이 없어 선택적 메모리 측정은 null로 기록하며 패키지를 강제로 추가하지 않는다.
- 회전 반사/왕복, flat-hand identity, 잘못된 회전 거절, 입력·모델·설정 변경에 따른 캐시 무효화 등4개 검사를 통과했다.
- 첫 HandFlow 실행은 입력 config와 HaMeR config 변수 이름 충돌로 실패했다. 수정 후 준비된 프레임/키포인트를 재사용해 외부 추론을 검증하고 최종 네이티브 전체 손 작업까지 재실행했다. 첫 실패 로그는 보존했다.
- 누락 파일 검증 보조 스크립트의 Unreal struct 참조 복원이 잘못돼 첫 시작이 거절됐다. 실제 작업이 없음을 확인한 뒤 경로를 복구했다. 초기 Python import probe는 Win32 OpenGL 설정 누락으로 실패했지만 실제 worker의 사전 설정 및 재검사에서는 정상 import됐다. 최초 Ultralytics import probe가 사용자 전역 settings.json을 기본값으로 재작성한 부수 효과가 있었으며, 실제 worker들은 job-local 설정 경로를 사용한다.
- source/model 출력, 네이티브 적용 결과, 인터페이스 캡처를 구분했다. 최종 육안 평가는 사용자에게 남겼다. 다른 영상, cook/package, 독립 리뷰는 하지 않았다. Git staging/commit/push 없음.
