# HandFlow 손 겹침 관측·회전 가속 안정화

2026-11-08, UE5.8.4 CL58902052, 동일 프로젝트/사용자 에디터 PID29012. [직전 HandFlow 개선](HandFlowRefine20261108.md)에서 남은 test2 5.5초 손 겹침과 증가한 회전 변화를 조사했다. 공통 Python 코드만 수정했다. 관절 제한, WiLoR 회전 혼합, 구간별 모델 교체, 모델 재학습, 컴퓨터 유즈는 없다.

## 확인한 원인

5.33~5.47초에는 오른손이 미검출된 채 양 손목이 가까워지고, 왼손으로 배정된 HaMeR 관측의 projected wrist가 반대쪽 ViTPose 손목에 더 가까운 프레임이 있었다. 예를 들어 frame164는 자기 손목까지16.84px, 반대 손목까지8.46px인데 검출 점수는0.722였다. 이는 실제 어느 손이 맞는지 확정하는 증거가 아니라 **관측 배정이 불확실하다는 근거**다. 기존 보정은 이 점수만으로 겹친 손의 손가락을 강하게 맞췄다. [관측 검토 그림](../../../Saved/CubelessBodyMocap/HandFlowOcclusion20261108/observation_review.png)에 원본/관측/양 손목을 기록했다.

또한 기존 영상 보정은 HandFlow 자세에 더하는 **보정량의 연속성**만 다뤘다. 원래 추정 자세의 급격한 변화나 프레임별 투영·깊이 불확실성이 섞이면 최종 손가락 회전은 여전히 급하게 바뀔 수 있었다. 증가량 상위에는 frame161 왼손 검지, frame211 오른손 중지 등이 있었다. 원시 모델과 Manny에서 같은 변화가 확인되어 이번 원인은 리타깃 변환이 아니다.

동일한 저장된 HaMeR 입력과 HandFlow 시간축 출력으로 다음을 분리 실험했다. 아래는 원시 손가락 회전 통계다.

## 공통 코드 수정

`Tools/handflow_image_guidance.py`에 두 기능을 추가했다.

1. **겹침 관측의 신뢰도:** HaMeR crop의 손목을 원본 영상 좌표로 복원한다. 양 손목이 가까우며 관측이 어느 손에 속하는지 불확실할 때 영상 재투영 항의 가중치를 부드럽게 낮춘다. 실제 손목 관측의 신뢰도도 반영한다. 손이 멀리 떨어진 정상 관측은 유지하고, 좌우를 바꿔 끼우거나 미검출을 검출로 만들지 않는다.
2. **최종 회전의 SO(3) 가속 항:** 연속 프레임의 상대 회전 변화에 부드러운 비용을 둔다. 절대 각도나 최대 속도의 상한은 없다. 회전 행렬을 사용해 axis-angle의 동치 표현을 점프로 오인하지 않는다. 일정한 빠른 각속도는 이 항의 벌점을 받지 않으며 영상 근거 항과 함께 최적화한다.

기존 residual prior0.03/continuity3과100회 Adam은 유지하고 최종 회전 가속 가중치6을 더했다. test2 프레임/초/손가락별 예외 규칙은 없다. `handflow_engine.py`는 이 신뢰도를 **영상 보정에만** 전달한다. 기존 검출, HaMeR 특징, HandFlow 시간축 추론은 동일하게 유지한다. `guidance_scores`, `ownership_reliability`, 손목 오차를 `model_evidence.npz`에 별도 저장하며 원래 scores/valid를 덮어쓰지 않는다. 모델·설치 환경·C++·네이티브 리타깃은 변경하지 않았다.

실제 test2에서 신뢰도를10% 넘게 낮춘 관측은 좌44/우9프레임이었다. 최소 reliability는 좌0.396/우0.507이었다. 이러한 수치는 정확도나 검출 복구율이 아니다.

5.5초 주변13프레임은 frame159~171, 약5.30~5.70초다. 이번 전체 최대 변화는3.63초(frame109)의 왼손 중지에서 발생했다. 원시 모델의 최대26.27454°와 Manny의26.27456°는 수치 오차 수준으로 일치한다.

7.7초에는 검지·새끼손가락을 편 제스처가 유지됐다. 원시 MANO 왼손 새끼손가락 PIP 굽힘0.80°→1.01°, 검지14.47°→13.82°로 상세 자세가 완전히 같은 것은 아니지만 펴진 형태는 유지된다. [이번 Manny 7.7초](../../../Saved/CubelessBodyMocap/HandFlowOcclusion20261108/manny_after_231_1.png)를 직접 확인했다. 7.03초에는 최대 변화가 더 작아져 직전 개선이 유지된다.

빠른 동작을 전부 약화했는지도 별도로 확인했다. 6.5~8.1초 왼손 PIP 움직임 범위는 검지100.29°→101.16°, 새끼손가락85.83°→83.10°였다. 독립 MediaPipe 2D 관측과 모델3D 곡률의 상관 proxy에서 검지 최적 시차는0→0프레임, 새끼손가락은0→1프레임이었다. 투영·가림·관측 오류가 섞이므로 실제 지연33ms나 지연0을 확정하는 측정은 아니다. 프레임 이동·리샘플링은 없으며 전체 클립을 사용하는 offline 처리다.

회전 변화가 모든 프레임에서 감소하지는 않았다. 예를 들어 frame84 왼손 검지 두 번째 관절은1.17°→7.99°가 됐다. 큰 변화가 주변 프레임으로 분산되는 효과가 있으며, 이번 증가분 상위도 기록했다. 이를 모든 프레임의 정확도 향상으로 표현하지 않는다.

## 성능·보존·실행 범위

- 전체 손 작업81.30→83.8초, 외부 worker57.74→53.99초. 단계별 실행 편차가 있으므로 속도 향상을 주장하지 않는다. 영상 보정 자체는2.01초였다.
- worker 프로세스 트리 RSS6753→6752MiB, CUDA 할당 피크2788MiB로 같은 수준이다. editor 피크10592MiB는 별도 수치이며 프로세스별 피크를 더하지 않는다.
- 처리 중 Slate callback248회, 최대 wall gap2.016초였다. 긴 추론은 비동기로 수행됐지만 순간 지연0은 아니다.
- 원시 valid/boxes/scores, HaMeR 관절/특징, camera, HandFlow `temporal_poses`, betas/translations는 직전 결과와 **정확히 같다**. 전체/global pose도 같다. 달라진 것은 손가락 영상 보정 단계다.
- 네이티브 저장 검사에서 비손가락123트랙×244샘플 차이0. 별도 AnimPose 평가의 양 손목도 원본/직전/이번 결과가 정확히 같다.
- 26장 동일 시각 캡처, 전체 손가락 회전 평가, 저장된 새 에셋 로드 및 직접 의존성 검사 완료. 새 MetaHuman/CBM/MCP runtime 의존성은 없다.
- 단위 검증: 2rad/frame의 일정한 빠른 각속도에 대한 가속 항은 수치 오차 수준0, 불규칙 변화에는 양의 비용, 1·2프레임 경계에서 유한 gradient, 미검출 가중치0 유지, 전혀 관측이 없으면 identity, global pose 불변. 실험과 최종 코드 출력 차이는 최대0.000118rad 이내였으며 최종 전체 worker/네이티브 실행으로 다시 검증했다.

새 검출을 얻은 것은 아니다. **5.5초 오른손 미검출과 숨은 손가락의 깊이·형태 불확실성, 손끼리의 관통은 남는다.** 이번에 확인한 개선은 불확실한 관측에 의한 과보정과 회전 튐의 감소다. 검출은 좌237/우172, 누락 좌7/우72로 그대로다.
