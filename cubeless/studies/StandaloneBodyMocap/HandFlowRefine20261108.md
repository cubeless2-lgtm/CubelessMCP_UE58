# HandFlow 시간창 경계·손 제스처 보존 개선

2026-11-08, UE 5.8.4 CL58902052, 기존 프로젝트/사용자 에디터 PID29012. 이전 [선택형 HandFlow 검증](HandFlow20261108.md)의 후속 작업이다. 모델 가중치 재학습이나 특정 애니메이션 수동 편집이 아니라 공통 외부 Python 추론 코드를 수정했다. 관절 제한·WiLoR 회전 혼합·구간별 모델 교체·컴퓨터 유즈는 사용하지 않았다.

## 원인 분리

기존 test2 전신, PNG 244프레임과 손 배정용 키포인트를 재사용하여 HaMeR 입력 특징/관절을 한 번 기록하고 시간축 조건을 분리 실험했다. 이전 HandFlow 원시 회전과 재현 결과의 최대 튐은 모두 frame211의 왼손 새끼손가락 75.0152°였다. 같은 현상이 Manny에서도 75.0152°이므로 리타깃 단계가 최초 원인이 아니다.

| 동일 HaMeR 입력 실험 | 7.03초 새끼손가락 변화 | 전체 최대 변화 |
|---|---:|---:|
| 기존: ODE 3회, 겹침 2프레임 | 75.02° | 75.02° |
| ODE 8회, 겹침 2프레임 | 74.94° | 74.94° |
| ODE 3회, 겹침 8프레임 | 17.61° | 43.72° |
| ODE 8회, 겹침 8프레임 | 21.76° | 48.59° |

frame211은 기존 stride14의 창 경계에 걸린다. 같은 입력에서 겹침만 넓혀 변화가 크게 감소했으므로 창별 문맥 전환이 주된 원인이라는 실험 근거가 있다. 단순히 ODE 횟수를 늘리는 방법은 채택하지 않았다. 현재도 기본 ODE는3회이며, 16프레임 창의 겹침을8프레임으로 확대했다. 모델의 velocity를 겹치는 창에서 결합하는 기존 vblend를 사용하며 다른 추정기 포즈를 섞지 않는다.

7.7초에는 HaMeR 관절 투영이 검지·새끼손가락을 편 원본 제스처를 잡고 있었다. HandFlow 시간축 출력이 그 관측을 충분히 보존하지 못했다. 입력 특징/좌우 배정/평균 손 자세를 교체할 근거는 없었으며, 추론 횟수나 창 겹침만 바꿔서는 제스처가 복구되지 않았다. [HaMeR 입력 관절 비교](../../../Saved/CubelessBodyMocap/HandFlowRefine20261108/hamer_input.png)를 남겼다.

## 공통 코드 변경

- `Tools/handflow_engine.py`: 창 겹침2→8, HaMeR 3D/2D 관측과 압축 특징 기록, 영상 근거 보정 연결. YOLO 설정 경로도 작업 폴더로 통일했다.
- `Tools/handflow_image_guidance.py`: 새로 작성한 MANO 재투영 최적화. HaMeR 2D 관측, HandFlow 자세로부터의 보정량에 대한 prior, 보정량의 시간적 연속성을 이용한다. 100회 Adam, prior0.03/continuity3.0이며 프레임별 임계 각도나 test2 시각 하드코딩은 없다.
- HaMeR 손바닥의 강체 정렬과 카메라는 투영 계산에만 쓰고 출력 손목에 적용하지 않는다. 변경 대상은 HandFlow의45개 손가락 axis-angle 성분이다. HaMeR 손가락 회전을 직접 복사하거나 평균내지 않으며 WiLoR 결과를 읽지 않는다.
- MANO 미분 계산은256표본 단위로 역전파해 큰 정점 버퍼를 제한한다. 전체 보정량의 시간 연속성은 유지한다. 검출 누락은 데이터 항의 가중치0으로 처리하며, 누락의 퇴화된 카메라 방정식은 풀지 않는다.
- 기존 공통 quaternion 좌표 변환과 Manny palm/terminal-axis 리타깃은 변경하지 않았다. 평균 손 자세를 중복 가감하지 않는다.
- `Tools/refine_handflow.py`: 전체 클립의 양방향 보정이라는 시간 문맥 정보를 기록한다. 16프레임 창을 엄격한15프레임 지연 한계로 해석하지 않도록 `offline_future_context_frames=null`로 정정했다.

`temporal_poses`는 영상 보정 이전 HandFlow 출력, `poses`는 보정 후 모델 출력이다. 새 정보와 목적 함수/시간은 `model_evidence.npz`, `metrics.json.image_guidance`에 기록된다. 기존 전신/손 캐시 분리는 유지하며 관련 Python 소스 해시가 바뀌므로 이전 손 추론 캐시는 자동 무효화된다. 기존 저장 에셋은 덮어쓰지 않는다.

참고 저장소의 고정 리비전과 모델은 이전과 같고 ThirdParty 런타임 파일을 수정하지 않았다. 새 보정 모듈은 Cubeless 구현이며 기존 HaMeR/MANO API를 호출한다. [기존 파일별 출처·조건](../../../Plugins/CubelessBodyMocap/ThirdParty/HandFlow/README.md)은 그대로 적용된다.
