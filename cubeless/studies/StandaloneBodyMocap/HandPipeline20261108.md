# test2 손 검출·회전 변환·Manny 리타깃 단계별 조사

> 후속 정정: 아래 회전값 전달 검사는 손바닥 기준축과 끝마디 축까지 검증한 것이 아니었다. 사용자의 추가 문제 제보 후 손바닥 기준 약 25도 차이와 끝마디 기준축 약 5~13도 차이를 발견해 수정했다. 또한 Slate 캡처가 백그라운드에서 이전 뷰포트 텍스처를 재사용할 수 있어, 아래 이전 시각 검증에는 한계가 있다. 현재 검증과 새로 강제 렌더링한 캡처는 [HandTrace20261108.md](HandTrace20261108.md)를 따른다. 기존 수치는 당시 정의한 회전값 비교 결과로 보존한다.

사용자가 요청한 순서에 따라 MediaPipe 검출 → SMPL 손 회전 → Manny 리타깃 → 최종 애니메이션 저장을 분리해 비교했다. 기존 전신 추론과 손목은 유지했다. 해부학적 관절 제한을 추가하는 단계는 진행하지 않았다. 사용자가 제공한 `C:/Git/mano_v1_2`도 연결하여 WiLoR 실제 결과를 함께 생성했다.

## 발견한 문제와 수정

1. **MediaPipe v2 회전 변환**: PIP/DIP의 굽힘 방향을 고정하고 각도/속도를 제한한 구현이 관측된 손가락 방향을 바꾸었다. 같은 test2 world landmark에 대해 재구성한 마디 방향 오차가 평균 22.3226도, 최대 176.9087도였다. v3에서는 부모 좌표계를 순서대로 전달하며 관측 방향으로 최소 회전을 구한다. 필터 전 방향 재구성 오차는 평균 약 0.000000253도, 최대 0.00000148도였다. 이는 landmark 전달 정확도이며 영상 정답과의 일치도가 아니다. 기존 고립 스파이크 제거·시간 필터·누락 보간·원본 복귀는 유지했다.
2. **부모 좌표계 불일치**: 임시 기준 자세로 리타깃한 손가락 로컬 회전을 기존 애니메이션에 그대로 붙였다. 실제 손목/손바닥 부모 자세가 달라 손이 뒤틀렸다. 같은 v2 입력으로 저장 부분만 바꾼 비교에서, 영향이 1인 샘플의 손목 상대 회전 오차가 평균 44.0538도에서 약 0.0000247도로 줄었다. 현재는 리타깃 결과의 손목 상대 전역 회전을 실제 출력 부모에 맞춰 다시 로컬 회전으로 만든다.
3. **Manny 메타카팔 중복 매핑**: SMPL에 없는 8개 손바닥 뼈가 fuzzy mapping으로 같은 손가락 체인에 연결되어 MCP 움직임을 두 번 받았다. 작업별 profile에서 해당 매핑을 `None`으로 만들고, 세 마디 손가락은 `OneToOne`으로 전달한다. 기존 Retargeter 애셋은 바꾸지 않는다. 체인 설정을 배열에서 제거하는 첫 실험은 엔진이 기본 설정을 다시 만들어 실패했다. 실제 매핑을 지우는 방식으로 수정했다.
4. **손가락 뿌리 위치**: 기존 애니메이션의 잘못 매핑된 손바닥 회전을 남겨 두면, 세 마디 회전이 맞아도 손가락 뿌리가 손목으로 돌아 들어갔다. 따라서 손가락 30개와 메타카팔 8개의 회전만 보강한다. 손목을 포함한 나머지 123개 트랙은 244프레임 모두 원본과 동일하다. 변경 트랙의 위치/스케일도 기존 값을 유지한다.
5. **비교 화면 표시**: 현재 보강 슬롯과 다른 애셋을 Preview Animation으로 선택하면 무조건 Original로 표시되던 문제를 수정했다. 이제 실제 원본일 때만 Original이며, 다른 애셋은 Selected asset과 경로 툴팁으로 구분한다.

## 최종 검증

- 입력: 바탕화면 `test2.mp4`, 490×750, 244프레임, 30fps. 이미 추출된 프레임과 ViTPose 배정 데이터를 재사용했다. 전신 추론은 재실행하지 않았다.
- UE 5.8.4, CL58902052, 동일 프로젝트의 사용자 Development Editor에서 빌드·적용·저장·재시작 후 로드를 확인했다. 별도 프로젝트나 컴퓨터 유즈는 사용하지 않았다.
- 원시 MediaPipe 회전 → 리타깃: 평균 약 3.50e-14도, 최대 약 1.03e-13도. 기존 중복 매핑은 평균 43.8810도, 최대 179.9811도였다.
- 최종 저장 결과와 리타깃 목표의 손목 상대 회전 차이: 원시 진단 최대 0.0000761도, MediaPipe 최대 0.0000821도, WiLoR 최대 0.0000799도. 원본 복귀를 의도적으로 섞은 샘플은 이 오차 계산에서 제외했다.
- 모든 출력은 네이티브 저장 전 123개 비편집 트랙 전체 프레임의 위치·회전·스케일 일치 검사를 통과했다. 원본 uasset SHA256 `3467bf2ddc8fa6004bd361d324cd70ef6b99337b39b4e225b9d3b79f57198694`는 유지되었다.
- 최소 회귀 테스트 4개 통과: 180도 방향 전환 시 distal 불변, 관측 신전/측방향 보존(양손), 단일 관절 고립 스파이크, 무검출 원본 복귀.
- 실제 플러그인 손 확대 뷰를 0초 왼손, 2초 오른손, 7초 왼손에서 원본·구 v2·MediaPipe·WiLoR로 확인했다. 손가락 뿌리가 손목 아래로 접혀 들어가는 구조적 오류는 개선됐다. 작은 손과 겹친 손에서는 검출 자세가 여전히 영상과 다르다. 전체 프레임의 해부학적 정상성이나 정답 정확도를 검증한 것은 아니다.

## MANO와 WiLoR

사용자 제공 `models/MANO_RIGHT.pkl`만 WiLoR `repo/mano_data/`에 복사했다. LEFT, UV, SMPL+H는 이 worker에 필요하지 않았다. 원본/복사본 SHA256은 `45d60aa3b27ef9107a7afd4e00808f307fd91111e1cfa35afd5c4a62de264767`로 일치한다. 제공된 라이선스를 `MANO_LICENSE.txt`로 함께 보관했다. 모델과 venv는 Git 제외 대상이다.

첫 실행의 `No module named dill` 오류를 보존하고 plugin-local WiLoR 환경에 `dill==0.3.8`을 추가한 후 실제 추론을 완료했다. 이 의존성은 requirements에도 기록했다.

| 항목 | MediaPipe v3 | WiLoR |
|---|---:|---:|
| 전체 프레임 | 244 | 244 |
| 왼손 검출 프레임 | 140 | 237 |
| 오른손 검출 프레임 | 105 | 139 |
| worker 기록 추론 시간 | 12.30초 | 43.80초 |
| PyTorch peak allocated CUDA memory | 해당 없음 | 2693.27 MiB |

시간은 디코딩·ViTPose·모델 로드를 포함한 전체 처리 시간이 아니다. 검출 수가 많다고 자세가 더 정확하다는 뜻도 아니다. WiLoR 출력도 가림/작은 손에 대한 추정 한계가 있다.

## 재현과 사용자 확인

1. `Original Animation`에 Test2_Comparison_20261108의 원본을 지정한다.
2. `Hand Result`에 `Saved/CubelessBodyMocap/HandPipeline20261108/MediaPipe/hands.json` 또는 `WiLoR/hands.json`을 지정하고 `Apply cached fingers`를 누른다. 모델 재추론 없이 새 애셋을 만들고 원본/보강 버튼을 복원한다.
3. `Left hand`/`Right hand` 확대와 yaw/zoom으로 확인한다. 시간은 영상과 공유한다. Backend 선택만 바꿔서는 이전 보강 결과가 바뀌지 않는다.
4. 새 영상 추론은 backend를 고른 뒤 `Refine fingers`를 사용한다. MANO 및 Python 경로는 플러그인 내부 설치를 사용한다.

출력은 `/Game/CubelessMocap/Test2_HandPipeline_20261108/Hands/`에 있다. 실제 최신 애셋 경로와 파일 해시, 빌드 로그는 `cubeless/records/verification/cbm-hand-pipeline-20261108.json`에 기록한다. 원본·이전 결과·실패한 진단 애셋은 덮어쓰지 않았다.

원시 자료는 `Saved/CubelessBodyMocap/HandPipeline20261108/`에 있다: `conversion_errors.json`, `stage_errors.json`, `final_stage_errors.json`, `ue_stages_final.json`, 각 worker 폴더, 단계별 PNG. `mapping_fix_error.json`은 설정 제거만 시도했던 **실패한 실험** 기록이며 최종 성공 수치로 사용하면 안 된다. 초기 캡처 중 일부는 수정 전 UI의 Original 오표기가 있으므로 파일명과 `applied_assets.json`을 함께 확인한다. 최종 handoff 캡처는 수정한 UI에서 다시 생성했다.

추후 관절 제한은 이번 변환 오류 수정과 분리해서 적용해야 한다. 독립 리뷰, 다른 영상, 배포/패키징 검증은 이번 범위에 포함하지 않았다.
