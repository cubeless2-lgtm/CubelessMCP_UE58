# 손가락 후처리: WiLoR 연결과 MediaPipe 비교

## 요청과 범위

사용자가 제공한 [GVHMR3 v13 키트](https://app.notion.com/p/40bdadb56b2f81049463efb200f5dfde)의 손 처리 코드를 확인하고 Cubeless Body Mocap에 손가락 후처리를 추가했다. MANO 다운로드가 사용자 브라우저에서 502 오류를 반환하자, 사용자가 MediaPipe를 추가해 먼저 비교하도록 승인했다. 기존 전신 추출 및 원본/고속 옵션은 유지한다.

## 구현

- `Finger Backend`: MediaPipe(기본), WiLoR.
- `Original Animation`: 손가락을 보강할 기존의 저장된 대상 애니메이션.
- `Refine fingers`: 같은 영상의 선택된 시작 시점부터 원본 애니메이션의 FPS/키 수만큼 처리한다. CHMR·Hue·접지 해결은 다시 실행하지 않는다.
- 손 위치 배정에 기존 ViTPose를 사용하고, 별도 Python 프로세스가 손 추론을 수행한다. 게임 스레드에는 모델 준비와 최종 애셋 작업만 올린다. 취소 시 소유한 외부 프로세스를 종료하며 원본을 변경하지 않는다.
- 몸의 좌우 손목과 후보 손을 대조한다. 짧은 누락은 quaternion 보간, 긴 누락은 원래 손가락 자세로 부드럽게 복귀한다. 스파이크와 중복 손 할당을 거른다.
- MediaPipe: 원본 해상도 손 영역의 21개 3D 관절을 손바닥 기준으로 정렬하고 최소 swing 회전으로 변환한다. 관절 방향이 손바닥 법선을 통과할 때 축 회전이 180도 뒤집히는 방식은 사용하지 않는다. 축 방향 twist는 독립 측정값이 아니다.
- WiLoR: v13과 같은 원본 모델, 왼손 영상 반전/회전 반사 방식. MANO 손 관절 순서를 SMPL에 매핑한다. 손목 회전은 교체하지 않는다.
- 기존 IK Retargeter로 손가락을 변환한 후, 원본 AnimSequence를 복제해 손가락 30개 회전 트랙만 적용한다. 위치·스케일·전신·손목·IK·보조 본·곡선·시간은 원본에서 유지한다. 저장 전 손가락 외 전체 트랙의 전 프레임을 비교한다.
- `Original body + fingers` / `MediaPipe fingers` 버튼으로 같은 영상 시점과 카메라에서 전환한다. 결과 라벨은 실제 생성한 백엔드를 따른다.
- `Hand Strength`와 `Hand Result` / `Apply cached fingers`: 이미 생성한 hands.json을 재적용하므로 추론 없이 강도를 바꿀 수 있다.

v13 전체 GVHMR/ExMR 프로젝트를 설치하지 않았다. 손목 수정·LD 리그 코드도 가져오지 않았다. 의존성·버전·가중치 출처와 해시는 플러그인의 `ThirdParty/README-Hands.md`에 기록했다.

- 미리보기 수정 후 0초/1초의 실제 렌더 자세 변화와 1초에서 원본/보강 전환을 PNG로 확인했다. 전체 재생 1,000표본의 영상/애니메이션 시간 차이는 최대 약 0.00000048초였다. 픽셀 presentation latency의 정밀 측정은 아니다.
- MANO 파일이 없는 WiLoR 요청은 작업 시작 전에 거절되며 Idle을 유지하는 것을 확인했다. 최종 빌드 오류/경고는 0개다. 사용자 확인용 에디터 PID 7752와 비교 창을 유지했다.

## 발견과 수정

1. 첫 실행은 Windows에서 UE가 진행 파일을 읽는 짧은 순간 Python의 atomic replace가 거부되어 실패했다. 원본은 보존되었다. 수치 추론이나 애셋 변경을 반복하지 않고 파일 publication만 짧게 재시도하도록 수정했다. 이후 전체 경로 실행에서 저장까지 성공했다. 최초 실패 profile은 `Hands_44BEBA6641ECA5C407F61587C0E9E521/profile.json`에 남겨 두었다.
2. Python 검증 스크립트의 UPROPERTY 접근은 `set_editor_property`를 써야 했다. 초기 직접 속성 대입 오류는 추출 시작 전 발생했다.
3. 비교 화면에서 영상 시간과 CPU 본 자세는 바뀌어도 렌더가 이전 자세에 머무는 현상을 확인했다. 자체 preview world에 수동 평가한 본 데이터를 업로드하도록 bounds/렌더 dirty 처리와 `SendAllEndOfFrameUpdates`를 추가했다. 기존 시간값 동기화 검사는 화면의 실제 픽셀 갱신까지 입증한 것은 아니었다.

## 검증 한계

후속 확대 리뷰에서 기존 결과의 관절별 roll 및 원본 복귀 블렌딩에 큰 튐이 확인되어 수정했다. 이전 시간 동기화·전신 보존 검사는 손가락 안정성을 입증하지 않았다. 현재 구현과 비교 근거는 [손가락 안정화 리뷰](HandReview20261108.md)를 참고한다.

MediaPipe 모델 로드, 좌표 반사, 기준 자세 항등성, 손목 방향 불변성, PIP 굽힘, 짧은/긴 누락 처리와 스파이크 필터, UE 빌드 및 test2 출력 저장을 확인했다. 품질은 정답 모캡 데이터와 비교하지 않았다. 새 영상/다중 인물/강한 가림, WiLoR 실제 추론, 패키징, 독립 검토는 수행하지 않았다. 손 전용 배정 단계는 현재 단일 인물이 명확한 영상 기준이다.

WiLoR 코드·가중치·CUDA 환경은 준비되었으나 사용자별로 받아야 하는 `MANO_RIGHT.pkl`이 없어 실제 실행은 미검증이다. MediaPipe는 이 파일을 사용하지 않는다. 설치된 외부 환경·모델은 Git 제외 대상이며, MetaHuman 플러그인 의존성을 추가하지 않았다.
