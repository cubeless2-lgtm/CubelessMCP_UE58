# test2 문제 구간: 손바닥·끝마디 기준축 추적

사용자는 손이 뭉개져 보이는 캡처를 제시하고, 모델 출력 → 회전 변환·관절 축 → Manny 리타깃·블렌딩 순서로 확인하여 처음 발견되는 전달 오류부터 수정하도록 요청했다. 관절 제한은 이후 단계로 남겼다. 이번 변경은 손 리타깃 기준축과 비교 캡처에 한정한다. 새로운 모델·관절 제한·충돌 보정은 넣지 않았다.

## 구간과 단계별 확인

- 최초 에디터 상태는 수정 전 MediaPipe 결과, 3.2000743초였다. 이후 사용자 확인 과정에서 7.6916723초도 관측했다. 3.2초(96프레임), 7.7초(231프레임) 양손과 0초 양손·2초 오른손을 비교했다.
- **모델 출력**: 기존 test2의 원본 영상 프레임, MediaPipe 2D/3D landmark, WiLoR 회전 출력을 재사용했다. 모델이나 전신 추론을 반복하지 않았다. MediaPipe 244프레임 중 검출은 좌140/우105프레임이다. 96프레임 왼손은 미검출이며 앞뒤 검출을 보간한다. 오른손과 231프레임 양손은 검출되었다. 작은 손의 픽셀/깊이 불확실성과 겹침이 남는다. 모델 출력이 영상 정답과 완전히 일치한다고 판단하지 않았다.
- **회전 변환**: 검출된 245개 손 표본 × 15개 마디에서 MediaPipe 원시 3D 방향과 현재 v3 회전으로 복원한 방향을 비교했다. 평균 2.53e-7도, 최대 1.48e-6도였다. 기존 필터 전 방향 전달에서 추가로 큰 오류를 찾지 못했다. 축 비틀림의 정답을 측정했다는 뜻은 아니다.
- **리타깃**: 손바닥 기준 방향이 source/target에서 좌24.866도, 우26.641도 달랐다. 이전 검사는 월드 회전값이 목표대로 전달됐는지만 비교해 이 차이를 놓쳤다. 자식 뼈가 없는 끝마디는 FK 자동 정렬 대상에서 빠져 약4.917~12.517도의 기준축 차이도 남아 있었다. 이번에 확정하고 수정한 추가 전달 오류다.
- **블렌딩**: 문제 구간 96/231프레임은 양손 영향이 1이다. 96프레임 왼손은 모델 누락 보간이지만 원본 자세와의 혼합은 아니다. 원본 혼합 때문에 생기는 문제와 구분했다. 기존 시간 필터·원본 복귀 정책은 바꾸지 않았다.

## 수정

`CBMHands.inl`은 손목 및 검지/중지/새끼 첫 관절 위치로 source와 target의 손바닥 좌표계를 계산한다. FK 결과의 손가락 방향을 이 좌표계에 맞춰 전달한 뒤 실제 출력 부모에 맞게 로컬 회전을 계산한다. 손목·전신과 손바닥 뼈의 기준 위치는 그대로다.

끝마디는 Manny 바인드의 들어오는 마디 축(대략 local +X/-X)을 사용해 source의 끝마디 방향 규약에 맞춘다. 각도 상한·굽힘 방향 강제·추가 속도 제한을 적용하지 않는다. 공유 Retargeter 애셋도 변경하지 않는다. 현재 입력 JSON을 `Apply cached fingers`로 다시 적용하면 새 기준축 보정이 적용된다.

관측된 굽힘 면으로 MCP 비틀림을 추정하는 별도 실험도 했다. 진행 방향만으로는 비틀림 정답을 확정할 수 없고 정상 구간의 보존이 입증되지 않아 기본 solver에 채택하지 않았다. 실험 애셋은 `/Game/_MCP_Temp/HandTrace/CubelessTests/20261108/`에 있으며 최종 결과와 분리했다.

## 비교 수치

244프레임에서 영향이 1인 마디 표본 6,285개를 비교했다. 서로 다른 뼈 길이를 위치 오차로 혼동하지 않도록 각 손바닥 좌표계에서 마디의 단위 방향을 비교한다. 끝마디는 바인드의 실제 축을 사용한다.

| 저장 RAW 애니메이션의 방향 전달 오차 | 변경 전 평균 | 변경 후 평균 | 변경 전 최대 | 변경 후 최대 |
|---|---:|---:|---:|---:|
| MediaPipe | 18.75952° | 0.0000185° | 38.10915° | 0.0001461° |
| WiLoR | 19.90299° | 0.0000188° | 36.93799° | 0.0000645° |

이 수치는 **전달 과정의 오차**이며 영상 정답과의 손 자세 정확도는 아니다. 보정된 손목 상대 목표 회전과 저장된 RAW 결과의 최대 차이는 MediaPipe 0.000168도, WiLoR 0.000077도 미만이다. 원본 복귀 혼합 구간은 의도적으로 다르므로 이 일치 검사에서 제외했다.

최종 두 출력 모두 손가락30+메타카팔8 회전 외의 123개 트랙 ×244프레임 위치·회전·스케일 일치 검사를 통과했다. 원본 uasset SHA256은 `3467bf2ddc8fa6004bd361d324cd70ef6b99337b39b4e225b9d3b79f57198694`로 유지되었다.

## 실제 표시와 검증 보정

- 기존 `TakeScreenshot`만으로는 백그라운드에서 이전 뷰포트 텍스처를 읽었다. 이번 조사 초기 231프레임 좌/우 캡처가 동일 해시인 것으로 확인했다. `PrepareScreenshot`에서 현재 자세·카메라를 평가하고 viewport draw 및 render-thread flush 후 픽셀을 읽도록 수정했다. 추출 중 상시 비용이 아니라 명시적 캡처 시에만 수행한다.
- 수정한 캡처로 0초 양손, 2초 오른손, 3.2초 양손, 7.7초 양손을 변경 전 MediaPipe·변경 후 MediaPipe·변경 후 WiLoR로 총21장 비교했다. 이전 포즈가 재사용되는 캡처를 최종 시각 근거로 쓰지 않는다.
- 3.2초 실제 표시 컴포넌트와 동일 Manny 메시/리타깃 평가 설정의 pose를 비교했다. 32개 손/손가락 본의 최대 회전 차이는 0.00000242도, 위치 차이는 0.0000846cm였다. 에셋 트랙 검사와 실제 메시 표시 검사를 구분했다.
- 초기 표시 검사는 메시를 지정하지 않고 skeleton 평가 및 리타깃 OFF로 비교하여 최대0.1519도/0.00602cm 차이가 있었다. quaternion 정규화나 RAW/Compressed 변경만으로는 해결되지 않았다. 설치된 `AnimPose.cpp`의 OptionalSkeletalMesh/ShouldRetarget 처리와 컴포넌트 설정을 확인하고 평가 조건을 맞춘 뒤 통과했다. 초기 실패 기록은 보존했다.
- 초기 끝마디 검사도 오른손 축을 정확한 -X로 가정하여 0.00138도 잔차를 만들었다. 실제 바인드에는 작은 Y/Z 성분이 존재했다. 실제 축을 사용한 검사로 고쳤으며 0.001도 허용 기준을 늘리지 않았다.
- UE5.8.4 CL58902052, 동일 사용자 프로젝트의 Development Editor 빌드 성공(최종13.87초). Python solver는 바꾸지 않아 기존 unit test를 반복하지 않고 변경된 네이티브 경로의 전 프레임 재적용/저장과 실제 표시를 검증했다. 별도 프로젝트·컴퓨터 유즈·Git stage/commit/push는 사용하지 않았다.
