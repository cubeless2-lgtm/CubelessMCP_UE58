# 하체 깊이 순서와 발바닥 접지 보완 — 2026-11-08

사용자가 test3 약7.68초에서 뒤쪽 다리가 앞으로 침범하고 발가락이 들리는 현상을 지적했다. 기존 하체 조정 자체의 깊이 오류를 확인했다. 사용자는 추가로 **접지 구간의 발목·발가락 회전 보완을 허용**했다. 관절 제한과 FootMR 재도입, 손 모델 혼합은 하지 않았다.

## 원인과 수정

- 기존 하체 목적함수는 골반의 카메라 깊이만 붙잡고 개별 다리 관절의 깊이는 거의 자유롭게 두었다. 옆모습의 겹치는 다리에 2D 직선 무릎 관측을 강하게 적용하면서 뒤쪽 다리가 앞으로 이동했다. test3 프레임231의 왼쪽−오른쪽 발목 깊이는 원본 +29.95cm에서 기존 하체 보완 −8.67cm로 부호가 반전됐다.
- `lower_body.py`에 원본 대비 각 관절의 상대 깊이와 좌우 순서를 유지하는 부드러운 관측 항을 추가했다. 옆으로 향할수록 깊이 근거를 강화하고, 2D 직선 무릎 근거를 약화했다. 하드 관절 각도 제한은 아니다. 원본 전신 깊이가 정답이라고 보장하는 기능도 아니다.
- 원본 신발 스키닝 정점의 최저 높이를 이용해 하체 위치 보완이 이미 있던 침투를 그대로 물려받지 않게 했다. 수평으로 미끄러지는 발을 공중으로 오인하지 않도록 추가 접지 판단에는 높이와 수직 속도를 사용한다.
- 프레임230에서 발가락 로컬 회전은 거의 기준 자세이고, 앞꿈치가 들린 주요 원인은 원본 전체 발 방향이었다. 발목 월드 회전을 고정한 위치 보완만으로는 이 문제를 해결할 수 없다.
- 새 `support_contact.py`는 대상 신발 밑창과 스키닝 가중치로 발목 월드 회전·앞꿈치 로컬 회전을 맞춘다. 발마다 밑창64개 표본, 부드러운 지면/침투/원본 자세/시간 연속성 항을 사용하며 원래 신발 밑창의 굴곡을 유지한다. 접지 확률이0인 프레임은 회전 보완을 적용하지 않는다. 전환 구간에서는 확률에 따라 연속적으로 반영한다. 본 축을 임의 추측하거나 발목 회전 보정을 중복 적용하지 않는다.

## 선택과 보존 범위

1. `Lower Body > Foot Input Animation`에는 하체 보완 전 전신+HandFlow 결과를 넣는다. 이미 보완한 결과의 중복 입력은 거절한다.
2. `Refine Pelvis and Legs from Video (Experimental)`을 켠다.
3. `Refine Supported Ankle and Forefoot`는 선택 사항이다. 꺼짐: 모든 프레임의 발목 월드 방향과 발가락 로컬 트랙을 보존한다. 켜짐: 지지/전환 구간에만 발목·앞꿈치 회전을 허용한다.
4. `Refine pelvis / legs` 실행 후 `Before legs`와 `Pelvis / legs`로 원본 전신+HandFlow / 최종 결과를 전환한다. 비교용 위치 보완 단독 결과도 별도 애셋으로 저장했다.

두 옵션 기본값은Off, 손 기본값은HandFlow다. 위치 단독은 `_VideoLegs_`, 접지 회전 포함은 `_VideoLegsSupport_`로 새 애셋을 만든다. 기존 애셋을 덮어쓰지 않는다. 공통 상체 역보상과 HandFlow 원본 데이터는 유지한다. native 적용 전 상체 월드 자세와 공중 발 회전을 검증하고, 저장 전 위치/스케일 및 보호 대상 트랙을 비교한다. 위치 단독153개, 접지 포함151개 로컬 트랙이 정확히 보존됐다. 공중 프레임의 발목/앞꿈치 월드 오차는 native 포즈 평가에서 최대0.000188°였다.

새 두 모드 모두 전체 프레임에서0.5cm 이상 침투가 없었다. 다만 지면에 모든 밑창 정점이 완전히 붙지는 않는다. 프레임230 오른발 앞꿈치는−0.075cm, 뒤꿈치는1.42cm다. 회전이 바뀌며 발바닥 중심의 수평 이동이 늘어난 구간도 있다. 미끄러짐이 모든 구간에서 개선됐다고 결론 내리지 않는다. 지지 속도는 후보와 무관한 기존 SMPL 지지 마스크로 측정한 스키닝 밑창 중심 속도다.

영상 관측 재투영 오차p95는 기존 하체14.79/18.90px에서18.10/22.39px로 증가했다. 보완 전 전신35.29/33.73px보다는 낮지만, 2D 맞춤 일부를 양보하고 깊이를 보존한 결과다. 이 관측은 최적화 입력이므로 독립 정답이 아니다. test3 프레임601 오른무릎 굽힘7.62→8.19°로 기존 정면 지지 다리 개선은 대체로 유지됐다.

발목 월드 회전의 프레임 간 변화p95는 test2 좌/우17.06/16.32→17.02/16.16°, test3 13.99/13.96→13.09/13.55°였다. 하지만 test2 약3.33초 오른발의 최대54.85° 변화, test3 약12.83초 왼발31.92° 변화는 남는다. 원본에도 각각55.40/31.92°가 있으며, 특히 공중 구간은 이번 보존 계약에 따라 바꾸지 않았다. 새 접지 보완을 전반적인 회전 튐 해결로 해석하지 않는다.

- 프로젝트 Development Editor 빌드 성공22.11초. 기존 에디터를 정상 종료하고 같은 프로젝트 PID31828로 재실행했다. 별도 Unreal 인스턴스나 CUA는 사용하지 않았다.
- 네 결과의 native 저장/전체 프레임 평가, 보호 트랙 검증, 공중 발목을0.15rad 손상한 결과의 무애셋 거절을 확인했다. source 애셋과 선택 결과는 유지됐다.
- native 동기 비교 캡처: test3 프레임230/235/601, test2 94/165/231의 기존/새 결과12장. 최종 화면은 test3 7.6827731초, 새 접지 포함 애셋이다. Lumen GI/반사, temporal AA, motion blur는Off이며 밝은 기존 비교 조명을 유지한다.
- 진행 파일 교체가 Windows 읽기 핸들과 겹쳐 WinError5로 실패한 기록을 보존했다. Python의 동일 파일 교체에 한정해 제한된 재시도를 추가하고 오류 로그를 상태 파일보다 먼저 쓴다. 이후 네 native 작업은 정상 완료했다. 접지 확률 필터의 부동소수점 미세 음수/1초과도[0,1] 범위로 정규화했다. 관절 각도를 제한한 것은 아니다.
- 종료 준비 스크립트가 readonly 비교 속성 설정에서 거절된 후 실제 상태를 확인했다. 쓰기 가능한 설정만 복원했고 Foot Result도 정상 최종 JSON으로 다시 연결했다. HandFlow/WiLoR 단축 비교 참조는 재실행 후 비어 있지만 `Before legs`는 정확한 HandFlow 애셋을 가리킨다. 손 모델을 다시 실행하거나 불필요한 복제 애셋을 만들지 않았다.
