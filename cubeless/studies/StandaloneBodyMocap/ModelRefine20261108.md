# test2 손 모델 입력·좌우 배정 후속 개선

사용자는 3.2초 검출 누락, 5.5초 손 겹침, 7.7초 WiLoR 새끼손가락 오류와 현재 프레임의 돌출된 손가락을 추가 조사하도록 요청했다. 수정 범위는 **모든 영상에 사용하는 플러그인의 입력/관측 처리 코드**다. test2 애니메이션의 특정 프레임이나 손가락을 수작업으로 고치지 않았고, MediaPipe·WiLoR 학습 가중치와 MANO 모델은 변경하지 않았다. 관절 제한도 추가하지 않았다.

## 원인과 수정

### 3.2초: 관측 복구

원본/넓은 크롭에서 검출되지 않던 f95~96 왼손은 반사 입력이나 180도 회전 입력에서 검출됐다. 새 `hand_observations.py`는 기존 크롭, 넓은 크롭, 좌우 반사, 180도 회전을 순서대로 시도하며, 신뢰할 수 있는 해당 손의 관측을 찾으면 중단한다. 원본 좌표로 돌아올 때 2D 위치와 3D world landmark의 XY를 모두 역변환하고, 반사한 입력의 Left/Right 라벨도 되돌린다.

f96은 반사 입력을 통해 직접 관측을 얻었다. 이전 상태2(보간)에서 상태1(직접 관측)로 바뀌었다. 원본 영상과 관절을 겹쳐 보아 손의 위치·대략적인 손가락 방향을 확인했다. 가려진 관절의 3D 깊이 정답까지 측정한 것은 아니다.

### 5.5초: 좌우 교대 배정과 검지 돌출

사용자 에디터는5.5139276초에 멈춰 있었다. 표시된 본 좌표를 화면에 투영해 동그라미 부분이 **왼손 검지**임을 확인했다. 과거에는 손목 거리 위주로 배정하고 모델 좌우 라벨을 무시했기 때문에 겹친 손이 L/R로 번갈아 들어갔다. 예를 들어 f163~164의 Left 관측이 오른손에 들어가고 f165의 불확실한 Right 관측이 왼손에 들어갔다.

새 공통 경로는 원본 좌표 기준으로 복구한 좌우 라벨, 분류 신뢰도, 몸의 손목과의 거리, 겹침 중 최근 동일 손 관측의 존재를 함께 사용한다. 손목이 가까울 때 한 손의 라벨 변경만으로 가려진 다른 손의 추적을 새로 시작하지 않는다. 손목이 분리되면 다시 검출할 수 있다. 두 크롭에서 얻은 후보를 모아 배정하므로, 다른 쪽 크롭에서 검출된 실제 왼손도 왼손 후보로 사용할 수 있다. 손가락의 위치/각도를 특정 자세로 강제하는 코드는 없다.

f163·164·166의 왼손 관측을 회복하고 f165의 불확실한 관측은 받아들이지 않았다. 따라서 f165 왼손은 앞뒤 같은 손 관측으로 보간하고, 가려진 오른손은 감쇠/원본 복귀 정책을 사용한다. 같은 시점의 실제 Manny 캡처에서 표시된 검지가 옆으로 길게 돌출되는 현상은 개선됐다. 두 손의 충돌/교차가 완전히 해소되었다는 판정은 아니다.

원인 분리를 위해 시간 필터를 거치지 않은 원시 회전도 별도 진단 애셋에 적용했다. 원시 자세 자체가 불안정했고 필터를 단순히 제거하는 것으로 해결되지 않았다. 이 진단 결과는 최종 애셋에 채택하지 않았다. 최종 변경에서 기존 보간/평활화 함수의 관절 각도 조건은 추가하지 않았다.

### 7.7초: WiLoR 입력 후보 선택

공식 기본 padding2.0에서는 왼손 새끼손가락이 접혔고, padding1.3/1.6에서는 원본처럼 펴졌다. 다른 구간은 더 좁은 입력이 반드시 좋지 않으므로 고정값을 일괄 변경하지 않았다.

새 `hand_crop_consensus.py`는 독립적인 MediaPipe 관측이 있을 때 WiLoR의 기본2.0과 후보1.6 입력을 비교한다. WiLoR가 예측한 카메라로21개 관절을 원본 영상에 투영하고, 원본 좌표의 MediaPipe 관측과 비교한다. 후보는 정규화 거리0.03 이상 및15% 이상 개선할 때만 선택한다. 이 기준은 영상상의 관절 위치 차이이며 관절 제한이 아니다. WiLoR 회전을 MediaPipe 회전으로 대체하지 않는다.

f231 왼손은1.6을 자동 선택했다. 정규화된 독립 관측과의 평균2D 차이는0.09581→0.03604였고, 실제 원시 MANO 메시와 최종 Manny에서 새끼손가락이 펴지는 것을 확인했다. 이 수치는 정답 모션 오차가 아닌 **두 추정 결과 사이의 일치도**다. 전체 선택은7개 손/프레임 표본(f103,211,212,229,231,232,235 왼손)이었다. 특정 영상명·프레임·새끼손가락에 대한 분기 없이 선택했다.

독립 관측은 현재 플러그인의 MediaPipe 환경/모델이 설치되어 있으면 별도 프로세스로 자동 생성한다. 명시적인 `landmark_reference` 캐시는 입력 frame_dir·frames·fps·source_asset 및 keypoints 해시가 맞는 경우만 허용한다. MediaPipe가 없거나 참조 worker가 실패 종료하면 기존 WiLoR 크롭으로 동작하고 `landmark_reference_available:false`를 남긴다. `adaptive_crop:false`는 기존 WiLoR 크롭 경로를 선택한다. 자동 참조 실행은2프레임 smoke test로 확인했고, 전체244프레임 비교에서는 방금 생성한 동일 입력의 MediaPipe 관측을 검증 후 재사용했다.

MediaPipe는 이전 관측 중 L55/R48개를 제외하고 L29/R4개를 새로 얻었다. 관측 수를 늘리는 것보다 손의 정체가 불확실한 관측을 사용하지 않는 쪽으로 바뀌었다. 제외한 모든 관측이 정답 기준으로 잘못됐다고 증명한 것은 아니며, 다른 영상에서 보수적인 거절로 손실이 생길 수 있다.

시간은 동일 test2 캐시를 이용한 각 worker의 단일 측정값이다. 전신 추출·디코딩·모델 로드·UE 저장을 포함한 총시간이 아니며, 엄격하게 통제한 성능 벤치마크도 아니다. 이번 WiLoR123.51초에는 참조 MediaPipe 재추론이 포함되지 않았다(캐시 확인0.021초). 새 영상은 독립 관측 생성 비용이 추가된다. WiLoR CUDA peak allocated는2,698.25MiB였다. 이번 변경은 속도 개선으로 보고하지 않는다.
