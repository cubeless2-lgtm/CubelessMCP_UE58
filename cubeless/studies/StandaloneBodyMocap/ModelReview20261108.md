## 확인한 문제와 수정

### MediaPipe 입력 크롭

기존 크롭에서 검출하지 못한 손을 더 넓은 문맥 크롭에서는 검출했다. 예를 들어 f90 왼손, f103 왼손, f106~108 오른손에서 원본의 손 위치·대략적인 손가락 방향을 따라가는 관절이 복구된다. 크롭을 항상 넓히면 기존 성공 검출까지 달라지므로 채택하지 않았다.

`refine_mediapipe.py`는 기존 `radius=max(48,1.4*size)` 검출을 우선한다. 수용할 후보가 없을 때만 `max(48,2.0*size)`로 한 번 재시도한다. 모델 confidence 기준, 몸의 손목과의 거리, 반대 손목과의 거리 검사를 동일하게 적용한다. 두 손에 같은 손이 배정되면 재시도 후보가 기존 primary 후보를 밀어내지 못하게 했다. 검출 메타데이터에 크롭 범위·배율·모델 좌우 라벨/점수를 남긴다. 좌우 라벨 점수는 정확도 점수가 아니다.

최종 비교에서 기존 검출 245개를 모두 유지했고, 해당 3D landmark의 최대 차이는 **0**이었다. 새로 68개의 손/프레임 표본을 추가했다. 이는 정확한 자세 정답 68개를 확보했다는 뜻이 아니다. 저해상도·가림·깊이 추정 오류는 남는다.

### 시간 필터의 잘못된 결측 판정

공통 `clean_rotations`는 현재 자세가 앞뒤와 각각 40도 이상 다르면 앞뒤 자세가 서로 다른 경우에도 현재 검출을 버리고 보간했다. 수정 전 MediaPipe에서 해당한 표본은 L75, L129, R80, R104, R212였다. 이때 앞뒤의 평균 마디 회전 차이는 약50.72~103.43도로, 비슷한 자세 사이에 삽입된 단발성 튐이라는 근거가 없었다.

앞뒤 자세도 서로 비슷할 때만 단발성 튐으로 제거하도록 수정했다. 기존 임계값 40도를 사용한 **결측 판정 조건**이며 관절 각도를 40도로 제한하지 않는다. 정상적인 빠른 전환을 보간으로 지우지 않는 회귀 테스트와, 실제 복귀형 단발 튐은 계속 제거하는 테스트를 추가했다. 기존 MediaPipe의 마디별 튐 검사, 짧은 결측 보간 길이, Gaussian 평활화, 긴 결측의 원본 복귀 정책은 유지했다.

WiLoR test2에서는 기존 제거 표본 L21의 앞뒤 차이가26.37도로 조건을 충족했다. 저장된 원시 출력에 수정 필터를 다시 적용한 결과 회전·가중치·상태 배열이 기존과 **정확히 동일**했다. WiLoR의 소실/오추정이 해결됐다고 주장하거나 결과를 불필요하게 재생성하지 않았다.

시간은 동일 캐시 프레임을 사용하는 손 처리 단계의 단일 실행 측정이며, 전신 추출·영상 디코딩·UE 저장을 포함한 총시간이 아니다. 검출 재시도 비용이 약5.1초 증가했다. WiLoR 원시 메시 진단 실행의 worker 측정 시간은34.05초, CUDA peak allocated는2,693.27MiB였다. 이번 요청에서 전체 파이프라인 메모리 성능을 다시 측정하지 않았다.

- Python 회귀 테스트6개 통과. 숫자 유한성·quaternion 단위 길이 검사 통과.
- 같은 사용자 UE5.8.4 CL58902052 에디터 PID32592에 새 MediaPipe 결과를 적용하고 저장했다. C++ 변경·에디터 재시작·별도 에디터·컴퓨터 유즈는 없었다.
- 손가락30개와 metacarpal8개 회전 외의 **123개 트랙×244프레임이 원본과 정확히 동일**함을 native 적용 검사가 확인했다. 원본 uasset SHA256은 이전과 동일하다.
- f103L, f107R, f165L에서 기존/수정 애니메이션을 동일 시점으로 native 캡처했다. 이 검사는 표시 연결과 잔여 문제를 확인하며 모델의 3D 정확도를 보증하지 않는다.
- 새 결과: `/Game/CubelessMocap/Test2_ModelReview_20261108/Hands/Body_DC5AF0E84CC150606168F0B22FE0423D_MediaPipe_81DFD102`.
- 기존 비교 결과/원본은 보존했다. 에디터는 새 결과와 test2를 연결하고 사용자가 두었던 약5.514초 왼손 뷰로 돌려두었다.
- 실행 기록: `cubeless/records/verification/cbm-model-review-20261108.json`. raw 입력·모델·수정 소스 해시와 출력 경로를 기록했다. Git stage/commit/push는 하지 않았다.

재현은 각 `MediaPipe_Baseline`, `MediaPipe_Final`, `WiLoR_Baseline`의 `request.json`과 별도 venv를 사용한다. 이전 결과를 보존하려면 `work`를 새 폴더로 설정하고 `keypoints.f32`를 복사한 뒤 해당 worker를 `--config`로 실행한다. 실행 이전 소스 사본은 같은 진단 폴더의 `refine_mediapipe_before.py`, `refine_wilor_before.py`에 있다. 전신 모델을 다시 실행할 필요는 없다.

## 남은 모델 오차

- **3.2초 왼손**: MediaPipe는 재시도 후에도 미검출이다. 앞뒤 표본으로 보간하며, 해당 프레임의 직접 관측으로 간주할 수 없다.
- **7.7초 왼손**: 원본의 펴진 새끼손가락을 WiLoR 원시 MANO 메시가 접힌 형태로 추정한다. 언리얼에 전달되기 전에 존재하는 오류다. MediaPipe는 두 개의 펴진 손가락 방향을 더 잘 따라가지만 접힌 마디의 3D 정답까지 확인한 것은 아니다.
- **0초 왼손**: WiLoR 원시 카메라/메시 투영이 실제 손보다 작게 나타난다. 공식 투영식을 사용한 원시 출력이며, 이 표시 크기 오차가 곧 손가락 로컬 회전 오차라는 뜻은 아니다.
- **5.5초 겹치는 양손**: 두 모델 모두 가림과 자세 불확실성이 남고 오른손은 미검출이다. Manny에서도 손의 벌어짐·겹침이 남아 있다. 검출 누락 개선만으로 해결되었다고 판단하지 않았다.

원본 영상의 2D 대조로 위치/실루엣/명백한 펴짐 차이는 확인할 수 있지만 가려진 관절의 깊이·축 비틀림 정답은 확정할 수 없다. 이번 결과는 모델 전체의 품질 합격 판정이 아니다. 관절 제한·충돌 보정은 다음 단계로 남겼다.
