# 수동 마커, 자동 키 표시와 본 선택 수정

사용자는 임의 시각의 보정 마킹, 자동 마커의 슬라이더 표시, 3D 본/선과 클릭 범위 3배 확대를 요청했다. 이어 원하는 본과 다른 본이 선택되는 현상을 보고했다. 기존 c++1218 승인 범위의 CBMEditor UI/API만 수정했다. 기존 영상·Quinn HandFront_v4·추론 파이프라인·리그·Anim BP는 보존한다.

대표 프레임 배열과 자동 프레임 배열을 분리하고, 수동 삽입 시 현재 Slerp 보정값을 상속하며 뒤의 Sample 인덱스를 옮긴다. 추가/삭제는 기존 Undo 스냅샷에 프레임 배열까지 포함해 한 단계로 처리한다. 자동 키는 삭제를 거부한다. session version2의 auto_frames로 출처를 저장하고 기존 세션도 복원한다. 같은 입력의 대표 분석을 다시 하면 기존 마커 시각/보정값을 새 자동 키와 합쳐 보존하는 코드를 추가했다. 재분석 병합 분기는 소스 검토 수준이며 이번에 추론을 다시 실행하지 않았다.

SCBMPlaybackSlider에 청록 A 마름모 자동 키, 주황 M 사각형 수동 키, 노란 선택 키와 흰 보정 점을 그린다. 위 마커 행 클릭은 대표 자세 선택으로, 아래 빨간 레일의 드래그/키 탐색은 기존 seek로 연결한다. UI의 mark/unmark와 명시적 프레임 API는 같은 도메인 함수를 사용한다. 실제 입력 테스트 대신 네이티브 API 및 엔진 렌더 스크린샷으로 확인했다.

기존 HCBMPoseBone은 자식 본에서 부모까지의 선을 자식 이름으로 판정하고, 확대된/겹친 hit proxy의 렌더 순서에 의존했다. 수정 후 마우스 좌표를 같은 FSceneView로 투영한 관절점에 대조한다. 보이는 3cm 관절 반경(기존1cm의3배) 안에서 거리 우선, 0.1px 내 겹침은 깊이 순으로 판정하고 Shift+클릭은 후보를 순환한다. 연결선은 부모 본으로 선택한다. Alt 카메라 조작을 보존한다. selected_bone을 노란 굵은 이름으로 표시하며, 동일 선택 코어를 PickPoseBoneAt API로 노출했다.

연결선은 한 픽셀 선 3개를 나란히 그려 3배 굵기로 만들고, 관절은 반경3cm 원/십자로 표시한다. 기존 두꺼운 PDI 선이 화면을 가리던 문제를 피하면서 hit-test 영역은 확대했다. 물리 스켈레톤/메시 스케일은 수정하지 않았다.

동일 프로젝트 UE5.8.4 Development Editor 빌드가 성공했다. 도메인 검증: 수동 키11개 추가(자동5개와 별개), 중복 추가의 멱등성, 자동 삭제 거부, 범위 거부, 삽입/삭제 Undo/Redo, 기존/새 세션 복원과 잘못된 자동 키 출처 거부. 비가환 회전(다른 키의 yaw10/pitch15)을 가진300프레임의 삽입 전후 spine_01 회전 차이는0도였고 원본 V4 SHA256은 동일했다. 새 테스트 에셋2개는 고유 /Game/_MCP_Temp/PoseMarkers/CubelessTests 아래 저장했다.

UI 검증: 4초 수동 마킹, 그 시각의5도 보정, Undo/Redo, 수동 삭제/Undo/Redo, 자동 삭제 거부, 재생/정지 및 스크린샷의 마커·본 확대 확인. 선택 검증: 관절 중심24곳 모두 해당 본, 겹친 후보4곳 순환, 분리된 연결선5곳의 부모 선택 및 빈 공간/뷰포트 밖 거부. 첫 검증 스크립트의 괄호 오타는 Python 구문 오류로 실행 전에 실패했으며, 보존 후 스크립트를 고쳐 검사를 완료했다.

증거는 cubeless/records/verification/pose-markers-20261115/의 domain-validation.json, ui-picking-validation.json, 스크린샷, build-picking.log와 final-verdict.json이다. 검사용 마커/각도와 이력을 제거한 상태로 같은 프로젝트 에디터를 사용자에게 열어 둔다. Computer Use/다른 프로젝트/독립 에이전트/커밋/푸시는 사용하지 않았다. 물리 마우스/키 입력, 독립 리뷰, 재분석 병합의 실행 검증 및 새 패키지/배포 ZIP은 미실시다.
