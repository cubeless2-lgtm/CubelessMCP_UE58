# test2·test3 접지 결과 재검토와 수정 — 2026-11-08

직전 [깊이·접지 보완](LegDepthAndSupport20261108.md) 결과를 기준으로 전체 프레임을 재검사하고 문제 구간을 영상과 대조했다. 수정 대상은 공통 Python 하체/접지 계산이며 HandFlow, 전신 신경망 가중치, Manny 리타깃, C++은 변경하지 않았다. 관절 제한과 FootMR은 추가하지 않았다.

## 확인한 원인

1. 하체의 미끄러짐 목적함수는 실제 발바닥이 아닌 발목 피벗의 수평 이동을 억제했다. 발목이 정지해도 신발 회전 때문에 밑창이 움직일 수 있다. 원본 수평 속도가 높으면 기존 지지 판단이 약해져, 이미 미끄러지는 발을 보정하기 어려웠다.
2. 접지 회전 단계는 보정 회전의 차분만 매끄럽게 했다. 원본 회전이 흔들리거나 앞꿈치 보정이 변하면 최종 밑창은 여전히 이동했다. 하체 단계에서 맞춘 발목 위치와 이후 신발 회전 간에도 차이가 생겼다.
3. 수정 후보의 약한 접지 전환에서 별도 회전 억제 가중치까지 접지 신뢰도를 곱하자 억제가 과하게 약해졌다. test2 프레임86에서 원본23.87°의 회전 변화가 후보37.90°로 증가해 이 후보는 최종본으로 선택하지 않았다.

## 공통 코드 수정

- `lower_body.py`: 원본 발목 월드 방향 보존을 전제로 실제 스키닝 밑창 중심의 발목 대비 오프셋을 구하고, 밑창 이동을 기준으로 하체를 맞춘다. 수평 미끄러짐이 있는 원본도 신발 높이/수직 속도로 확인한 지지 근거를 유지한다. 골반/다리 깊이 순서 관측은 그대로 둔다.
- `support_contact.py`: 최종 스키닝 밑창 이동과 최종 발목/앞꿈치 회전 곡률을 목적함수에 추가했다. 접지 진입/이탈의 이웃 프레임을 함께 보되 공중 프레임의 보정은0으로 유지한다. 보정으로 원본보다 큰 회전 변화가 생기는 경우 부드러운 시간축 관측 항을 추가했다. 이 항에 접지 신뢰도를 중복 적용하지 않는다. 회전각 자르기, 각도 범위/관절 한계, 강제 발 고정은 없다.
- 위치 단독 모드와 접지 포함 모드의 보호 계약은 동일하다. 접지 포함 모드151개 로컬 트랙(HandFlow 손 포함)이 정확히 보존됐고 상체 월드 자세를 유지했다.
- 새 시간축 residual에서2프레임 입력도 처리하도록 배열 형태를 명시했다. 공중2프레임은 모든 로컬 값이 정확히 유지됐으며 한쪽 접지2프레임도 유한한 결과로 완료됐다. 이 단축 입력 검사는 Python solver 범위다.

## 화면 리뷰와 성능

동기 비교 창에서 각 시점의 직전/수정 결과16장을 저장하고 다음을 검토했다.

- test2 2.87초: 회전하며 착지하는 구간. 후보에서 새로 생긴 큰 회전 변화를 억제했다. 원본 영상과 다리 벌림/체형의 차이는 여전히 있다.
- test2 5.10초: 지지 발 미끄러짐이 컸던 구간. 밑창 위치 변화가 줄었다.
- test2 7.03/7.70초: 접지 전환과 기존 제스처 구간. HandFlow 손은 동일하며 자세가 완전히 영상과 같아진 것은 아니다. 일부 전환 프레임의 미끄러짐 최대값은 여전히 남는다.
- test3 7.67초: 옆모습의 다리 앞뒤 순서와 앞꿈치 개선을 유지했다.
- test3 16.87/17.43초: 오른발 지지/이동 전환을 원본 영상과 대조했다. 자세를 강제로 고정하지 않으면서 이동량을 줄였다.
- test3 20.03초: 정면 지지 다리 굽힘 개선을 유지했다.

정지 포즈만으로 시간축 품질을 확정하지 않았고, 전체 프레임의 회전/정점 이동 수치와 함께 판단했다. 최종 연속 재생 육안 평가는 사용자가 이어서 할 수 있다.
