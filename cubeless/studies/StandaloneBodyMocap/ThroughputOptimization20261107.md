# Cubeless Body Mocap 추가 병목 최적화 — 2026-11-07

같은 dance01.mp4의 0~10초, 30FPS, 300프레임, 발 고정, Manny/기존 Retargeter를 사용했다. 모든 실행에서 체크포인트를 끄고 FFmpeg 디코딩부터 저장까지 다시 계산했다. 기존 입력 PNG 300장과 새 입력 전부 SHA256이 일치했다. UE5.8.4 CL58902052, RTX5060 Laptop에서 실행했으며 사용자 요청에 따라 현재 시스템 설정을 유지했다. OS/엔진/드라이버 캐시는 warm 상태다. 단일 실행 비교이며 전원/온도/클록까지 고정한 통계 벤치마크는 아니다.

## 구현

- SAM2 decoder의 두 고해상도 Conv를 같은 FP32 가중치 그대로 encoder 끝으로 이동했다. 사용하지 않는 pos_enc0/1 출력을 제외하고 encoder CPU 출력 전송량을 168MiB에서 20MiB로 줄였다. 모델은 새 에셋으로 추가했고 원본은 보존했다.
- 메모리 bank의 일시적인 깊은 복사를 동기 범위의 읽기 전용 view로 대체하고, 배열 전치를 32원소 타일로 처리했다. 소유 배열 변경 전에 bank 조립을 끝낸다.
- 고속 모드 PIL resize는 독립적인 32행 묶음을 백그라운드 우선순위 ParallelFor로 처리한다. 각 픽셀의 정수 합산 순서가 같고 각 패스의 모든 작업이 끝나야 다음 패스/버퍼 해제로 넘어간다. UObject 접근은 추가하지 않았다.
- `Fast Mode (Off: Original)`을 끄면 원본 CHMR/SAM2, 켜면 통합 CHMR/compact SAM2를 쓴다. 호환 Python 속성은 `use_fused_chmr`이다. 고정 시드 카메라 안정화는 양쪽 공통이다. 원본은 비교 기준이며 정답 동작이나 더 좋은 품질을 보증하는 모드라는 뜻은 아니다.
- 프레임·해상도·가중치·정밀도·Hue 50회·발 고정 설정은 유지했다. v5 캐시 키에 계산 경로를 포함했다. `cbm.CompactSAM 0`은 이전 고속 SAM2/직렬 전처리 비교용이며 일반 기본값은 1이다.

이번 추가 개선은 기존 고속보다 **3.63% 단축**했다. 원본 대비 **39.69% 단축**했다. 전체 RAM 피크는 키포인트 모델이 좌우해 큰 감소가 없었다. 개선 고속의 GPU 전용/공유 표본 최대는 4.538/2.567GiB, 완료 후 RAM은 4.453GiB였다. API 55회, 중앙 0.093초, Slate 최대 틱 공백 1.255초였다. 처리 내내 응답은 있었으나 로드·GC·저장의 짧은 대기는 남는다. 직접 마우스 조작 검증은 하지 않았다.

원본 전체 실행은 최종 행 병렬화 추가 직전 빌드에서 측정했다. 해당 경로의 원본 CHMR는 이후 변경하지 않았고, 최종 빌드의 기존 고속 시험은 원본 SAM2/직렬 전처리 경로를 검증한다. 원본 재실행의 단계별 f32 파일은 이전 기준 원본과 전부 바이트 일치했다. 최초 compact 단독 후보 실행은 화면 FPS 진단이 섞여 최종 시간 비교에서 제외했다. 최종 고속 두 경로는 같은 빌드/에디터에서 연속 실행했으며 화면·전원 설정을 변경하지 않았다.

## 품질 수치

기존 고속→개선 고속의 저장된 Manny 161본×300프레임 RAW 비교에서 위치 최대 차이 0.000000000cm, 회전 최대 차이 0.000000000도였다. quaternion acos 비교의 극소수치 오차는 별도로 구분한다. 단계별 f32 바이트 일치 여부는 JSON에 포함했다.

원본→개선 고속의 전체 본 회전 평균 0.010054도, 최대 1.279967도였다. 손목 최대 차이는 왼쪽 1.279967도, 오른쪽 0.556197도였다. 주요 25본 위치 최대 차이는 0.073045cm였다. 이 수치는 원본 대비 차이이며 영상 정답 대비 정확도가 아니다. 시각 검수·다른 영상/장치·CPU fallback·패키징·독립 C++ 검수는 수행하지 않았다.

## 제외한 후보와 복구

SAM2 memory attention 통합 후보는 별도 모델 시험에서 약 4%의 작은 단계 이득과 미세한 FP32 차이가 있어 채택하지 않았다. 화면 최대 FPS30 진단은 같은 15초 구간마다 CHMR 24프레임으로 이득이 없었고 이전 값0으로 복원했다. 실행 제품은 화면 갱신/전원 설정을 변경하지 않는다.

첫 compact 통합 실행은 package-only FSoftObjectPath.ResolveObject가 null을 반환해 원본 모델로 fallback하면서 4/6 출력 binding 불일치로 에디터가 종료됐다. 기존 사용자 결과는 보존했다. GT에서 명시적으로 LoadObject를 사용하고 compact 쌍의 명시적 지정 및 입출력 descriptor 검사를 추가해 작업 초기화 오류로 처리하도록 수정했다. 수정 후 전체 실행과 최종 빌드가 통과했다. 실패 기록도 삭제하지 않았다.
