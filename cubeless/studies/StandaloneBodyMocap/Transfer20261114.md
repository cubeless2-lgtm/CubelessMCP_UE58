# 원본 Markerless 설치 없이 PC 이전하기 — 2026-11-14

요청: 필요한 전신·손 모델을 따로 묶어 같은 이용자의 다른 PC에서 CubelessBodyMocap만 설치해 사용한다. 기존 계산·정밀도·품질과 직접 제어 API를 유지한다. Computer Use는 사용하지 않는다.

## 결과와 설치

- 실제 Release: `Saved/CubelessBodyMocap/Transfer20261114/Release/`. 전체 폴더를 복사하며 ZIP은 미리 풀지 않는다.
- 플러그인/DLL/FFmpeg, 전신, 손, 독립 Python 런타임, Manny 의존성의 5개 팩이다. 압축 약 13.13 GB, 설치 데이터 약 18.23 GB. 설치 전 대상 드라이브 여유 공간 약 35 GB가 필요하다.
- Windows x64, UE 5.8.4 CL58902052 / Editor BuildId55116800. HandFlow는 NVIDIA/CUDA 12.8 호환 환경을 요구한다. 다른 엔진 빌드는 설치 전 거절한다.
- `Install-CubelessMocap.ps1 -Project <실제 .uproject> -Engine <UE 설치 폴더>`를 사용한다. UE 내장 Python 3.11을 설치기의 표준 라이브러리 작업에만 사용하며, UE Python에 pip 패키지를 설치하지 않는다.
- 프로젝트에 CubelessBodyMocap/PythonScriptPlugin, Manny 사용 시 ControlRig/ControlRigSpline을 활성화한다. 변경 전 .uproject를 정확히 백업한다. 원본 Markerless와 MCP는 새 PC의 필수 설치 항목이 아니다.
- 자세한 설치·검증·소스 재생성 절차: `Plugins/CubelessBodyMocap/TRANSFER.md`. 공개 배포가 아닌 같은 이용자의 PC 이전용이다. Epic/MANO 등 기존 모델·코드 이용 조건과 고지를 유지한다.

## 구현

`model_pack.py`가 ZIP64, 파일별 SHA256, 엔진/BuildId, 안전한 상대 경로와 설치 영수증을 관리한다. 모든 선택 팩의 기존 파일 충돌을 먼저 확인하며 다른 파일은 덮어쓰지 않는다. 각 팩 전체를 임시 폴더에서 해시 검증한 뒤 배치한다. 전체 프로젝트에 대한 원자적 롤백은 제공하지 않으며 실패 시 부분 완료 목록을 출력한다. Windows 긴 경로는 확장 경로로 처리하며 OS 설정을 바꾸지 않는다.

`build_transfer.py`는 Git HEAD 7d3a9e2b82a70cfb4fa3e4ed0b4a16e53400157d의 소스에 이번 설치 도구/문서만 얹고, 기존 작업 환경의 run_hand_worker.py JSON bytes 읽기 한 줄을 명시적으로 포함한다. 이 기존 로컬 수정은 이번 작업에서 수정하지 않았다. 공개 Git 배포나 커밋은 수행하지 않았다. PDB, 개인 캐시, 중간 ONNX, 테스트 영상·애니메이션, 미채택 CHMR layout 실험은 제외한다. 준비된 모델은 변환·양자화·재계산하지 않는다.

기존 HandFlow venv를 복사하면 WiLoR .pth와 원래 Python 설치에 의존했다. CPython 3.12.10의 실제 바이너리/표준 라이브러리/선택된 의존성을 모아 상대 _pth를 사용하는 독립 실행 배치를 만들었다. Torch 2.8.0+cu128과 기존 모델/소스를 유지하며, 원래 환경에서 빠져 있던 Seaborn 0.13.2만 공식 휠 SHA256 확인 후 새 팩에 추가했다. 원래 가상환경은 바꾸지 않았다.

`prepare_content.py`는 설치 영수증 검증을 원본 Markerless 검색보다 먼저 수행한다. 준비된 팩 설치 후에는 원본 설치/모델 변환/다운로드가 필요 없다. 기존 소스 복사 경로도 유지한다. Manny 팩은 기존 프로젝트 Asset Registry에서 실제 메시·리타기터 의존성 108개 파일을 수집했다.

## 검증

- 5개 팩 전체를 .uproject 없는 소유한 staging 폴더로 복원하면서 내부 모든 파일의 SHA256을 확인했다. 별도 Unreal 프로젝트나 프로젝트 복사본은 만들지 않았다. 최종 플러그인 팩도 384개 파일 복원을 확인했다.
- 모델 복원 시 Python audit hook으로 원본 MetaHumanBodyTracker 경로 접근을 거절했다. `prepare_content --verify`는 존재하지 않는 원본 엔진 경로에서도 설치 영수증으로 전신 42개 파일 검증을 통과했다.
- 이동된 Python은 잘못된 PYTHONHOME/PYTHONPATH와 원래 WiLoR 경로가 주어져도 새 폴더 내부만 사용했다. Torch/NumPy/SciPy/OpenCV/SMPLX/Seaborn 등 import, CUDA, MANO 778 vertices 생성과 pip check를 통과했다.
- 기존 실제 프로젝트의 정상 Development Editor에서 원본 Markerless를 비활성화한 상태로 전신 32프레임 추론을 완료했다. TrackingBoxes/Keypoints/CHMR_Tokens MD5는 이전 기준값과 정확히 같았다. 실제 프로세스에 CBM 4개 DLL만 로드됐으며 MetaHumanBodyTracker DLL은 없었다.
- 이동된 Python과 이동된 손 모델을 실제 플러그인 설정에 지정해 HandFlow 32프레임 추론을 완료했다. 네트워크 연결과 원본 WiLoR/MetaHumanBodyTracker 읽기를 거절하는 test-only sitecustomize hook을 켠 상태였다. 84.3969초, 손가락 이외 123개 트랙 최대 차이 0. 훅 활성 상태를 별도로 확인한 뒤 staging에서만 제거했으며 최종 ZIP에는 포함하지 않았다.
- UE 내장 Python 3.11.8에서 설치기 10개 테스트를 통과했다. 잘못된 ZIP/경로/해시/엔진/기존 파일, 긴 Windows 경로, 원본 없는 영수증 확인을 다뤘다. 실제 프로젝트에 대한 read-only plan과 Editor 실행 중 쓰기 거절도 통과했다.
- C++ 소스 305개는 직전 UI/API 최종 기준과 모두 동일하다. 기존 계산/도구 328개 중 prepare_content.py만 의도적으로 변경됐다. 계산 코드, 모델 정밀도, 처리 기본값은 바꾸지 않았다. 이번 작업은 C++ 빌드가 아니라 기존 검증 DLL의 묶음/복원 검증이다.
- 소유한 Editor PID5704는 작업/dirty package/PIE가 없는 상태에서 정상 종료했으며 정확한 PID의 종료와 최종 로그를 확인했다.

## 실패 기록과 검증 한계

초기 runtime wheel RECORD의 역슬래시와 Windows 긴 경로 문제는 수정하고 재복원을 통과했다. 긴 경로 오류 시 게시된 파일은 0개였고 임시 폴더 정리도 확인했다. cp949 부모 콘솔 출력 오류는 실제 성공한 자식 로그를 UTF-8로 읽어 결과를 확인했다. 원래 실패 로그는 남겼다.

물리적으로 다른 PC에서 실행하지는 않았다. 현재 PC의 서로 다른 폴더에 복원한 환경을 검증했다. 전신 추론은 기존 프로젝트의 준비된 동일 바이트 모델을 사용했고, 손 추론은 staging 모델/런타임을 직접 사용했다. 다른 UE 버전, 독립 QA, 게임 패키징은 검증하지 않았다. 새 PC에서 모델별 라이선스가 사라지거나 공개 재배포 권한이 생기는 것은 아니다.
