# 접지 전환과 잔여 미끄러짐 보완

2026-11-09. 비교 기준은 바로 전 `StationaryFeet20261109` 최종 test2/test3 결과다. HandFlow와 기존 전신 추출은 재사용하고 하체 보완만 실행했다. 특정 영상이나 시간대를 코드에 지정하지 않았다.

## 원인과 변경

정지 관측이 시작될 때 속도 비용이 빠르게 커져 보정량 일부가 앞 프레임으로 이동했다. 이후 발목·앞꿈치 적합은 밑창 중심의 이동만 측정하므로, 중심 주변 회전으로 접지점이 움직일 여지도 있었다. 일반 접지 구간에는 추가 정지 관측이 없어 잔여 이동이 계속 남았다.

- `lower_body.py` v7: 9프레임 지속 검증을 통과한 정지 신호에 7프레임 대칭 전환을 적용했다. 접지 이동 비용을 `20+4*support`에서 `22+5*support`로 조금 높였다. 접지 진입·이탈을 포함한 발 위치의 2차 차분 비용을 최대 30%만 추가했다.
- `support_contact.py` v4: 일반 접지 이동 비용을 20→22로 조정했다. 정지가 관측된 경우 지면 가까운 밑창 표본들의 이동도 측정한다. 표본 가중치는 적합 시작 시 고정해서 발을 들어 비용을 회피하지 못하게 했다. 최종 밑창 중심 경로에도 약한 연속성 비용을 추가했다.
- 관절 각도 제한, 하드 발 고정, FootMR, 손 모델 혼합을 추가하지 않았다. 기존 깊이 순서 prior와 원본 전신·HandFlow를 유지한다. 코드 해시가 하체 캐시를 무효화하며 기존 저장 에셋은 덮어쓰지 않는다.
- 더 강한 평활화는 다리 깊이 순서를 뒤집거나 발 방향을 크게 바꿔 제외했다. 깊이 prior를 크게 높이는 후보도 골반 변화가 커서 제외했다. 선택한 후보는 `minimal`이며 원래 깊이 prior 강도를 유지한다. 전체 느낌의 최종 육안 판정은 사용자에게 남긴다.

## 보존과 상충 지표

- native 보존 검사에서 HandFlow를 포함한 보호 대상 151개 로컬 트랙의 차이는 0이다. 상체 월드 포즈도 보존한다.
- 골반 위치 변화 최대는 test2 0.131 cm, test3 0.542 cm이며 회전 변화 최대는 각각 0.626도, 0.567도다. 발 위치 변화 최대는 test2 0.849 cm, test3 1.409 cm다. 새 강한 다리 깊이 순서 역전은 두 영상 모두 0이다.
- 발의 회전 변화 최대는 test2 약 3.79도, test3 약 2.20도다. 모든 회전 연속성 지표가 좋아지지는 않았다. 프레임 간 발 회전 최대는 test2 왼발 28.71→29.04도, test3 오른발 26.01→26.32도로 소폭 증가했다. test2 오른발은 33.57→33.30도로 감소했다. 기존 큰 원본 회전과 일부 불균일은 남는다.
- native 전체 최저 스킨 높이는 test2 좌/우 -0.299/-0.273 cm, test3 -0.278/-0.359 cm다. 0.5 cm보다 깊은 침투 프레임은 없다. 완전 무침투를 주장하지 않는다. 일부 들뜸 지표도 소폭 증가했다.
- 미보완 공중 발의 원본 방향 차이는 native 평가 정밀도 범위(최대 약 0.000126도)다. 이전에 허용한 원본 공중 회전 오류 보완은 유지했다.

## 실행 증거와 재현

현재 프로젝트의 기존 Development Editor PID 31368 / UE 5.8.4 CL58902052에서 실행했다. test2 244프레임, test3 604프레임의 저장 결과를 native RAW pose로 평가했다. 별도 프로젝트·에디터, 컴퓨터 유즈, C++ 변경·빌드·패키지 검증은 사용하지 않았다.

worker 메모리는 에디터 전체 메모리와 별도다. 작업 중 Slate tick p95는 두 영상 약 31 ms, 최대 234/343 ms로 기록됐다. 비동기 진행이 유지됐지만 모든 순간 무정지를 보장한다는 뜻은 아니다.

후보 계산과 최종 설치 코드의 worker 포즈는 정확히 일치했다. 두 영상 모두 0초부터 끝(test2 8.1초, test3 20.1초)까지 비교 뷰 재생을 완료했다. 14개 native 캡처를 저장했고 일부 대표 화면을 직접 확인했다. 모든 프레임의 독립 육안 검증을 했다는 뜻은 아니다. 지난 검사 스크립트의 중복 0초 seek는 제거하고 뷰의 초기 열기 완료 시점을 확인하도록 고쳐 이번에는 두 영상 모두 완료했다. 제품의 미디어 재생 코드는 변경하지 않았다.
