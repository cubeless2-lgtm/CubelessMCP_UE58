# V4 자체 검수와 수정

2026-10-27. 사용자 요청에 따라 V3를 다시 검수했다. 독립 QA가 아닌 자체 리뷰다. 기존 한글 UI, 영웅별16프레임 대기, 점프와 적 피해30% 감소를 기준으로 한다.

## 발견 사항

1. **매우 짧은 클릭을 놓칠 가능성:** 기존 입력은 전 프레임의 버튼 누름 상태만으로 뗌을 판단했다. 같은 프레임에 눌렀다 뗀 경우 현재 눌림은 false이고 이전 눌림도 false여서 실행 조건이 성립하지 않았다. 새 `ApplyPointerV4`는 이번 프레임의 눌림 이벤트도 뗌 판단에 포함한다. 누르는 동안의 시각 상태, 같은 버튼 안에서 놓기, 화면 변경 시 취소와 중복 실행 차단은 유지했다.
2. **영웅 카드의 과한 색 덮개:** 커다란 사각형 채색과 테두리가 ImageGen 장식 프레임을 덮어 보였다. `SurfaceV4`에서 패널 안쪽만 은은하게 채색하고, 금색 선택·청록 오버·붉은 주황 누름은 안쪽 선과 밑줄로 강조한다. 기본 버튼의 붉은 바탕과 원래 장식을 살렸다.
3. **살아 있는 캐릭터의 체력이0으로 보일 수 있음:** 피해가 소수점이 된 뒤에도 표시는 정수 버림을 사용했다. 양수 체력은 올림으로 표시해0.4HP를1로 표시하고 실제0은0으로 표시한다. 실제 체력·피해·난이도는 바꾸지 않는다.
4. **점프 쿨다운 글자가 적과 겹쳐 읽기 어려움:** 전투 중 적이 글자 뒤를 지나는 장면을 관측했다. 글자 뒤에 작은 어두운 패널을 추가했다.
5. **게임 시간이 실제보다 느리게 진행됨:** 추가 확인에서 벽시계19.24초/월드18.99초에 게임8.54초를 관측했다. 갱신을 DrawHUD에서 Actor Tick으로 분리하고, 긴 프레임에서100ms 초과분을 버리던 경로를 없앴다. 전체 delta를 최대16개의 작은 단계로 나눠 처리한다. 입력은 Actor Tick마다 한 번 처리하고, 화면은 그리기만 한다. 표준 Engine 기능만 사용한다.

## 확인 결과

- 기존 마우스 위치/pressed/released PIE 입력19개 관측을 수정본에서 다시 확인했다. 메뉴, 영웅 선택, 강화, 일시정지, 재시작, 타이틀 이동과 드래그 취소가 정상 동작했다.
- 실제 Blueprint 함수에 같은 프레임의 눌림/뗌 신호를 주는 통제 시험7건에서 짧은 클릭, 다음 프레임 중복 방지, 누름 유지, 정상 뗌, 드래그 취소, 화면 변경 취소를 확인했다. OS 초고속 클릭을 직접 측정한 것과는 구분한다.
- 선택·오버·누르는 중·강화·전투·결과 화면을 검수했다. 원본 V3 증거를 덮어쓰지 않고 `vampire-survival-v4/`에 새로 저장했다.
- 실제 DrawHUD에 표시된 체력 문자열을 확인해0.4→1/85,0→0/85,76.6→77/85의3개 경계를 통과했다. 별도 `hp_display.json`에 기록했다.
- 시계 수정 전 샤미는 HP·시간·피해를 덮어쓰지 않고 외부 키 입력만으로 게임 시간105.68초,253처치,레벨9,체력49.1까지 관측했다. 벽시계230.54초의 검수 제한에 도달해 진행 중인 상태2에서 종료했다. 원시 드라이버의 `pass:false`는180초 승리 조건 미달을 뜻하며 패배가 아니다. 이 시간 차이를 추적해 위5번을 수정했으며 수정 전 정상 속도나180초 완주 증거로 세지 않는다.
- 최종 시계 검사는 벽시계3.203초, 월드3.20548초, 게임3.20548초였고 게임/월드 차이는 부동소수점 오차 수준이었다. P 정지 때 게임 시계가 멈추고 재개 후 진행하는 것도 확인했다. `clock_check.json`은 수정 전 관측, `clock_fixed.json`은 수정 후 결과다. Actor Tick 분리만으로 시간 차이가 남은 중간 검사도 원 도구 기록에 보존했다.
- 통제된 긴 프레임 단계 검사에서180초 승리 경계, 점프 최고점225px, 급강하 착지와10초 쿨다운을 확인했다. 정상 입력180초 완주를 의미하지 않는다. 입력 검사를 실행 중인 PIE에 다른 상태 검사를 동시에 적용한1회 간섭 실패는 `ui_input_interfered_raw_calls.json`에 보존했고, 새 PIE에서 순차 실행해 최종 결과를 확인했다.
- 정상 속도의 외부 키 입력 플레이 결과, 소수점 체력 표시 경계, 최종 컴파일/저장·의존성·패키징 상태는 같은 폴더의 `delivery_report.json`을 최종 기준으로 한다.

검증 코드와 제작 코드는 `review_v4.py`, `review_v4_graphs.py`, `review_hp_v4.py`, `review_clock_v4.py`, `review_stepper_v4.py`, `verify_review_v4.py`, `verify_clock_v4.py`, `play_review_v4.py`다. 생성한 그리기/갱신 소스도 기록 폴더의 `clock_fix_source.py`, `stepper_source.py`에 있다. 모든 실행 게임 로직은 표준 Blueprint다. 프로젝트·MCP·엔진 C++ 변경, Git stage·commit·push는 없다. 기존 V1~V3 에셋과 보고서를 보존했다.

Windows 패키지의 실제 OS 클릭은 V3에서 열린 방화벽 권한 창 때문에 대기 중이다. 해당 보안 요청을 자동 조작하거나 보안 설정을 변경하지 않았다. PIE 입력 검증과 패키지 OS 입력을 혼동하지 않는다. V4는 별도 경로로 새로 패키징하며 V3 실행 파일을 덮어쓰지 않는다. V4 패키지 실행 자체는 이번 검수에서 반복하지 않으며 이전 V3 실행 증거를 최종 V4 실행 증거로 바꾸어 주장하지 않는다.
