# V6: 10분 생존과 샤미 폭발·공격력 조정

2026-10-27. 현재 게임은 `/Game/VampireSurvival/Maps/L_CrimsonDawn`이다. [V5의 타격·드롭·버튼 변경](UPDATE_V5.md)을 유지하고 아래 항목을 조정했다. 검증 결과의 최종 기준은 `cubeless/records/verification/vampire-survival-v6/delivery_report.json`이다.

| 항목 | 현재 값 |

| 공격력 강화 | 한 번당 **×1.2, +20%**, 최대 5단계 |

“범위 30%로”는 30% 감소가 아니라 기존 반경의 30%로 해석해 알리고 적용했다. 효과의 직경은 135px이며 피해 판정 원과 일치한다. 원 면적은 기존의 9%가 된다. 특수 스킬의 출현 확률 20%, 최대 3단계, 주변 피해 60/75/90%는 유지한다. 일반 명중의 작은 기본 폭발 반경 65px도 유지한다.

공격력은 두 영웅 모두 강화마다 현재 공격력에 1.2를 곱한다. 샤미 22→26.4, 미니에 26→31.2가 첫 강화다. 5단계는 각각 약54.74/64.70이다. 공격력 외 일반 강화는 V5 수치를 유지한다. 기존에 설명한 “일반 강화 효과 2배” 전체를 1.2배로 바꾸지 않았다.

적 피해와 시간에 따른 체력 성장은 유지한다. 처음에는 종료와 보스 시점만 바꿨으나 일반 입력 샤미가81.86초에 사망해,3분 판의 초반 압박을10분에 맞게 분산했다. 박쥐15→50초, 중갑 망령40→133.33초, 돌진 적75→250초,2개체 발생60→200초,3개체 발생90→300초로 변경했다. 발생 간격 감소 계수도0.0028→0.00084로 조정했다. 공격력·특수 범위·적 피해·적 체력을 추가로 바꾸지는 않았다. 보스와 마지막 발생 간격의 시점은540초다. 보스 체력은 실제 생성 당시 최대 체력을 사용한다. 기존 UI의 고정1470 분모를 제거했다. 생존하면 정확히600초에서 승리하며 보스 처치는 필수가 아니다.

타이틀은 ImageGen으로 원래 고딕 도트풍을 보존하면서 **CRIMSON DAWN / TEN MINUTES**로 수정했다. 원본3분 로고와 V5 패키지는 보존했다. HUD 타이머·승리/패배 결과·강화 설명도 현재 값에 맞췄다. 남은 시간은 올림으로 표시해 첫1초 동안10:00이 보인다. 미니에 강화 설명은 “감속 · 출혈 피해”로 줄여 프레임 여백을 확보했다.

## 자체 검수

- 실제 Blueprint 함수로 두 영웅의 공격력 1.2배와5단계, 공격력 외 강화 유지, 샤미 특수 스킬3단계 모두의67.49px 안/67.51px 밖 판정,180초에 종료하지 않음,600초 종료와시간 고정,540초 보스·최대 체력, 강화 Engine pause/재개를 확인했다. `balance_checks.json`.
- 가속 내부 봇 전투는 일반 입력 플레이와 구분한다. `time_only_fixture.json`의600초 통과는 적/공격 생성 타이머를 늦춘 시간 경계 검사다. 후속 가속 전투에서는 적을 정상 생성하고 사망/승리까지 상태 전이를 검사했다. 이를 정상600초 완주로 주장하지 않는다.
- 실제 PIE 컨트롤러 마우스 입력10개 관측에서 누름 즉시 실행·영웅 선택/더블클릭·홀드 중복 방지·강화 중 실제 정지/재개를 확인했다. `input_pause.json`.
- 출현 시점과 물량 수정 후7개 경계에서 각30회씩 생성 수와 적 종류를 확인했다. `pacing_checks.json`. 일반 입력 플레이의 수정 전/후 결과는 별도로 기록했다.
- 실제 DrawHUD에서5개 화면의566개 글자 치수를 수집해 텍스트 박스 안 여백과 시작10:00·결과600초 표기를 확인했다. `layout.json`. 새 로고·강화·전투 화면도 검수했다.
- 최종 출현 속도로 샤미 일반 입력 플레이600초 생존 승리를 확인했다. 벽시계612.90초(강화 선택 시간 포함),3768처치,레벨44,최대 동시 적167,특수3단계였다. 달리기·점프를 관측했고 보스는9분에 등장했으나 처치하지 않았다. HP·시간·피해·경험치 덮어쓰기 없이 외부 키 입력만 사용했고 `TestBot=false`였다. 미니에의 정상600초 플레이는 이번 변경에서 반복하지 않았다.
- Blueprint90그래프 컴파일 오류0,39에셋의 금지 MCP 참조0을 확인했다. MCP·Toolset·Python 플러그인을 끈 콘텐츠 전용 프로젝트로 최종 Windows Cook/Stage/Package ExitCode0을 확인했다. 저장된 원본과 패키징 입력39에셋의 해시도 일치했다. 종료 시 PIE false·dirty0·자동 플레이/레이아웃 계측 CDO false였다. 최종 해시·패키징·일반 입력 플레이 결과는 최종 보고서에 기록했다.

`balance_v6.py`와 `pacing_v6.py`는 현재 그래프를 보존하는 일회성 핀 수정 스크립트다. 중간에 보스 변수 노드 제목을 잘못 가정한 검사 실패가 있었으며, 적용된11개 수정과 새 변수를 읽어 확인한 뒤 남은 연결만 이어서 작성했다. 전체 수정 요청을 재실행하지 않았다. 타이머 올림 처리의 정수→실수 변환 노드도 실제 연결을 따라 확인했다. 레이아웃 검사에서 실행형 모듈 import로 입력 검사가 실행된 실패는 기록하고, 공통 함수 정의만 로드하도록 검증 코드를 수정했다. 이 실행으로 V5 폴더의 일부 UI 자료가 V6 실행 결과로 갱신되어 해당 폴더에 별도 범위 주석을 남겼다. V5 패키지와 수치 검증은 보존했다. 불확실한 변경 재시도나 에디터 재시작·사용자 에셋 일괄 저장은 없다.

프로젝트·MCP·엔진 C++은 변경하지 않았다. V5와 마찬가지로 게임은 표준 Engine Blueprint로 실행한다. 별도 패키지의 RenderOffscreen 실행·타이틀 캡처도 확인하며 상세 범위는 `standalone_result.json`에 기록한다. 이는 실제 Windows 클릭이나 패키지10분 플레이와 구분한다. 이번 검수는 자체 리뷰이며 독립 QA와 네이티브 Windows 클릭 시험은 수행하지 않았다. 소스 이미지·프롬프트·패키지와 원시 호출은 V6 증거 폴더에 보존한다.
