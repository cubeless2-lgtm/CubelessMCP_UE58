# V7 회복 보상 감소

2026-10-27. 회복 보상 축소 요청과 이어진 “구슬도5%” 요청을 반영했다. 후자는 녹색 구슬의 회복량10%를5%로 줄이는 뜻으로 해석해 작업 중 알렸다.

| 항목 | V6 | V7 |
| --- | --- | --- |
| 최대 단계 강화의 대체 회복 | 체력60 | **체력20** |
| 녹색 구슬 회복량 | 최대 체력10% | **최대 체력5%** |
| 녹색 구슬 드롭 확률 | 2% | 2% 유지 |
| 빨간 경험치 구슬 드롭 확률 | 5% | 5% 유지 |

강화 카드의 기본 회복·최대 단계 대체 설명 모두 “체력20 회복”으로 맞췄다. 최대 체력 강화의+50 및 회복50,10분 길이,9분 보스,공격력 강화x1.2,샤미 폭발 반경0.9m 등 다른 V6 값은 유지한다. 최대 체력85의 녹색 구슬은4.25,최대 체력200에서는10을 회복하며 실제 회복량은 소수점을 유지한다. HUD 체력은 기존 올림 표시를 사용한다.

활성 Blueprint의 `UpgradeV5`, `UpgradeCardV5`, `UpdateGemV5` 네 핀만 수정했다. 새 그래프·런타임 클래스·C++은 추가하지 않았다. 원본 에셋을 V7 증거 폴더에 백업하고 컴파일·소유 에셋 저장을 확인했다.

실제 PIE 함수에 대한8묶음 검사에서7종 최대 단계 강화의20회복,최대 체력 제한,두 최대 체력에서5% 구슬 회복,녹색2%/빨간5% 드롭 경계,빨간 구슬 경험치,최대 단계 전 체력 강화 유지가 통과했다. 첫 검증의 최대 체력 제한 사례는 공격력 단계를 최대치로 설정하지 않은 검증 코드 오류였다. 실패 접두 기록을 보존하고 새 PIE에서 조건을 바로잡아 통과했다. 에셋 수정을 재실행하지 않았다.

증거는 `cubeless/records/verification/vampire-survival-v7/`의 `changes.json`, `compile.json`, `recovery_checks.json`, `isolation_manifest.json`, `package.log`, `delivery_report.json`이다. `recovery_v7.py`는 일회성 에디터 수정, `verify_recovery_v7.py`는 통제된 PIE 검증 코드다. Windows 실행 파일은 같은 폴더의 `Packaged/Windows/CrimsonVerify58.exe`다. 최종 저장 내용과 패키징 입력 해시를 대조한다.

V6의39에셋·90그래프와 MCP/Toolset/Python 비활성 패키징 구성을 그대로 사용한다. 이번 수치 변경 후10분 일반 플레이·네이티브 Windows 입력·패키지 실행·독립 QA는 반복하지 않았다. V6의600초 완주 결과를 V7 난이도 검증으로 바꾸어 주장하지 않는다. 현재 변경의 검증 범위는 회복 판정·표시 문자열·컴파일/저장과 갱신 패키징이다. 프로젝트·MCP·엔진 C++ 변경,Git stage/commit/push는 없다.
