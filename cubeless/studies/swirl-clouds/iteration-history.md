# 파노라마 소용돌이 구름 비교 스터디

## 현재 상태

사용자 제공 파노라마를 실제 비교용 스카이돔에 적용했다. 초기의 규칙적인 나선 띠는 레퍼런스와 닮지 않았다는 사용자 피드백에 따라 교체했다. 현재 볼륨 구름은 원본의 큰 틈과 소용돌이 영역을 형태 가이드로 사용한다. 기존 StormSky의 조명·대기·하늘·안개·노출은 유지한다.

- `/Game/Study/SwirlClouds/L_00_ReferencePanorama`: 원본 파노라마 비교용 스카이돔. 볼륨 구름은 숨긴 상태이다.
- `/Game/Study/SwirlClouds/L_01_LargeFlow`: 수정한 볼륨 구름. 비교용 스카이돔은 숨긴 상태이다.
- `/Game/Study/SwirlClouds/Materials/M_LargeFlow`, `MI_LargeFlow`: 별도 볼륨 머티리얼과 인스턴스.
- `/Game/Study/SwirlClouds/Reference/M_ReferencePanorama`, `T_ReferencePanorama`: 원본 표시 머티리얼과 텍스처.

두 레벨은 같은 PlayerStart 위치와 방향을 사용한다. 비교할 때 두 맵을 번갈아 열고 같은 카메라 방향을 사용한다. 에디터가 이전 시점을 유지하면 PlayerStart 위치로 이동한다. 주 비교 시점은 아래와 같다.

| 비교 영역 | 위치(cm) | Pitch | Yaw | FOV |
|---|---|---|---|---|
| 오른쪽 소용돌이 / 시작 시점 | -1424278.8, 595502.6, 200 | 32 | 119 | 90 |
| 왼쪽 넓은 구름층 | 동일 | 40 | -43 | 90 |

## 원본과 투영 방식

원본은 사용자가 첨부한 `codex-clipboard-d1f08b20-560a-4a17-80a7-dbf136acef2b.png`이다. 변경하지 않은 복사본은 [reference-panorama.png](reference-panorama.png)에 보관한다. 원본의 정확한 투영 메타데이터는 제공되지 않았다. 현재는 가로 360도, 세로 상반구 90도로 가정하여 매핑했다. 이는 확인된 원본 투영 규격이 아니라 비교용 설정이다.

스카이돔은 관찰 위치 중심의 양면 구체이며 원본을 Unlit으로 표시한다. EyeAdaptation 보정으로 비교 밝기 변화를 줄였다. 기존 하늘 재질과의 렌더링 충돌을 피하기 위해 비교 구체의 재질은 IsSky를 끄고 일반 불투명 표면으로 표시한다. 스카이 라이트의 실시간 캡처에서는 제외한다. 원본 표시 자체가 완성된 볼륨 구름은 아니다.

## 수정한 볼륨 구름

[large_flow.hlsl](large_flow.hlsl)은 현재 Custom 노드의 코드 복사본이다. 원본의 밝기에서 구름 영역과 높낮이를 유도하고, 세계 좌표의 Shape128/Erosion32 볼륨 노이즈로 표면과 가장자리를 변형한다. 원본 RGB를 최종 구름 색이나 발광으로 출력하지 않는다. 구름의 색과 조명은 기존 환경에서 계산된다. 규칙적인 코사인 나선 띠는 제거했다.

- CloudDensity: `0.002`
- FlowSpeed: `0.004` (세부 노이즈의 느린 이동)
- CloudAlbedo: `0.92, 0.94, 1.0`
- 구름 레이어: 기존 하단 5 km, 높이 10 km 유지.
- 다중 산란 octave: 2. PhaseG 0.1, G2 -0.1, Blend 0.2, 다중 산란 기여 0.55.
- 번개·깜빡임·발광 항 없음.

형태 가이드의 투영 중심은 위 관찰 위치에 고정되어 있다. 주변을 둘러보는 비교에 맞춘 구현이며, 장거리 이동에서도 같은 품질을 보장하는 자유 비행용 구름 시스템은 아니다. 또한 원본 음영을 높이로 해석한 근사이므로 실제 원본의 3D 형상을 복원한 것은 아니다.

## 실행과 검증

기존 프로젝트의 실행 중인 UE 5.8.4 에디터와 공식 MCP Python 실행 경로를 사용했다. 원본 PNG는 TextureFactory의 명시적 legacy import 정책으로 가져왔고, Interchange 상태 복원을 확인했다. 소스 코드나 프로젝트 C++는 변경하지 않았다.

원본 스카이돔과 볼륨 구름을 오른쪽 소용돌이 및 왼쪽 구름층의 동일 위치·방향·FOV에서 캡처하고 대조했다. 캡처 전 동일 시점에서 여러 프레임을 그려 시간 누적의 영향을 줄였다. 주요 기록은 `Saved/SwirlClouds/`에 있다.

- 원본: `reference_right_final.png`, `reference_left_final.png`
- 수정 결과: `revised_right.png`, `revised_left.png`
- 검증: `reference_comparison_verification.json`

두 맵의 저장과 재로드를 확인했다. 기준 스냅샷의 환경 액터 6개는 조사 대상 속성이 모두 일치했다. 볼륨/참조 표시 상태, 저장된 밀도 값, 미저장 패키지 없음, 6개 에셋의 직접 참조에 MCP/Toolset 의존성 없음까지 확인했다. 레벨 전환 시 Python 도구가 current_unknown을 반환했으나 재시도하지 않고 별도 호출로 실제 로드된 월드를 확인했다.

## 품질 한계와 다음 작업

큰 빈 공간과 소용돌이 배치는 첫 초안보다 원본에 가까워졌다. 그러나 가장자리의 밝은 테두리가 일부 선처럼 남고, 내부 덩어리와 말린 층의 입체감은 원본과 차이가 있다. 최종 고품질 완성 판정은 하지 않았다. 다음 수정은 테두리의 부드러운 부피 전이와 중간 크기 구름 구조에 집중한다.

이번 수정본은 에디터 뷰포트에서 검증했다. 초기 초안의 PIE 확인을 이번 수정본의 PIE 검증으로 간주하지 않는다. 장시간 애니메이션, 자유 이동, GPU 성능, cook·패키지 실행, 독립 QA는 미검증이다. 원본 학습 에셋은 변경하지 않았으며 새 작업은 커밋·푸시하지 않았다.


## 2026-11-15 밝은 테두리와 덩어리감 수정

위 비교 초안 이후 사용자가 요청한 테두리 완화와 입체감 수정을 적용했다. 현재 코드는 `large_flow.hlsl`에 동기화했다.

- Custom 출력 R은 소광 밀도, G는 경계의 산란 반응이다. 얇은 경계의 albedo를 낮춰 선처럼 빛나는 효과를 줄였다. 구름의 발광을 추가하지 않았다.
- 구름 단면을 둥근 밀도 프로파일로 바꾸고 기본 두께를 늘렸다. 약 1.5 km 규모의 추가 3D 노이즈로 덩어리의 높이를 달리했다.
- 주 소용돌이 중심은 높이마다 조금씩 회전하게 만들어 안쪽으로 말린 층을 표현했다. 원본은 mip 1을 사용하여 작은 각진 굴곡을 완화했다.
- L_01의 구름 view/shadow sample count scale을 각각 1에서 3으로 높였다. 환경 액터 6개의 조사 대상 속성은 그대로이다. GPU 비용은 측정하지 않았다.

같은 오른쪽/왼쪽 시점의 이전 결과와 대조하여 밝은 가는 선이 감소하고 두꺼운 안쪽 층이 드러나는 것을 확인했다. 일부 옅은 테두리와 전체적인 부드러움은 남아 있으며 원본의 최종 세부 품질과 같다고 판정하지 않았다.

현재 캡처: `Saved/SwirlClouds/rounded_banks_quality.png`, `rounded_banks_left.png`. 검증: `rounded_banks_verification.json`. 컴파일 오류 없음, 저장/재로드, 소스와 저장 노드 코드 일치, 샘플 수 설정, 환경 스냅샷 일치, 미저장 패키지 없음까지 확인했다. PIE/패키징/성능 검증과 Git 게시를 수행하지 않았다.

노드 작성 중 ComponentMask의 입력 이름을 Input으로 연결한 호출은 실패했다. 별도 조회로 생성된 두 마스크와 연결 없음 상태를 확인하고, 실제 빈 이름 입력에 연결하여 마무리했다. 실패한 생성 호출을 재실행하지 않았다.
